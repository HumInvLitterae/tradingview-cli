# v0.16.0 roadmap draft

This document records the `v0.16.0` direction after the `v0.15.0` release.

Status as of 2026-05-13: `v0.15.0` has been released. `tv compare` now has
additive movement readback for downstream percent-change evidence, and
`tv diagnose quote-data <SYMBOL>` can explain explicit quote-data source
availability without mixing scanner, chart, and quote-data values.

## Theme

`v0.16.0` is about quote-data session semantics, regular-session availability
clarity, and stabilizing browserless historical bars.

The goal is not to add another hidden fallback, make quote-data automatic,
rank symbols, or recommend trades. The goal is to make it clear why
`tv quote <SYMBOL> --source quote-data` can return structured unavailable
during regular session even when other quote surfaces have prices.

The first implementation slice widens the quote-data success readback without
changing sources: matching non-null `qsd.v.rtc` remains the preferred
after-hours/premarket-style candidate, and matching non-null `qsd.v.lp` can
now succeed as `price_readback.kind: "regular_last"` when `rtc` is absent.
This avoids reporting regular-session quote-data as unavailable only because
the after-hours-oriented field did not arrive.

After that compatibility slice, the next v0.16 implementation work stabilizes
`tv bars <EXCHANGE:SYMBOL>` as a Desktop-free historical bars command. This
removes the lab gate while keeping the undocumented WebSocket source boundary,
bounded request shape, and no-realtime-guarantee wording explicit.

## Lane 1: Quote-data regular-session semantics

Status: complete for the first v0.16 implementation slice.

`qsd.rtc` remains the strongest current candidate for the visible after-hours
or premarket style readback. For regular session, `qsd.v.lp` is exposed as a
separate `regular_last` quote-data readback rather than being merged with
scanner or chart prices. The payload keeps selected field evidence visible:

- `lp`;
- `regular_close`;
- `rtc`;
- `rch`;
- `rchp`;
- `current_session`;
- `market_phase`;
- `update_mode`.

The evidence should be public-safe. It should summarize counts and selected
field presence, not raw WebSocket frames, raw live payloads, target ids,
account-local metadata, or local validation details.

## Lane 2: Quote-data success semantics polish

Status: complete for the first v0.16 implementation slice.

`quote_data.v1` remains the command-local contract marker. The payload grows
additively with `quote_data.price_readback` and
`source_availability.price_readback_observed`. `rtc` and regular `lp` remain
separately labeled; `regular_close` is supporting context and does not make a
read successful by itself.

Do not infer session classification from absent fields. Do not synthesize a
single quote from scanner `extended_hours`, chart main-series bars, and
quote-data.

## Lane 3: Source choice workflow clarity

Regular-session price workflows should remain source-aware.

Scanner-backed `tv quote` and `tv quotes` are Desktop-free scanner REST reads
that can be delayed; inspect freshness metadata such as `time`,
`update_mode`, and `delay_seconds`. Chart-source quote reads the selected
chart main-series last bar. Quote-data is an explicit Desktop-backed
WebSocket quote-data readback whose current success path is centered on
`qsd.rtc`. `tv diagnose quote-data <SYMBOL>` explains quote-data availability
and target state, but it is not a blended quote source.

Docs and runtime skills should continue to teach that quote-data unavailable
means the current source readback did not produce the expected field inside
the bounded wait. It does not mean that the symbol has no market price.

## Lane 4: Stable browserless bars

Status: current implementation slice.

`tv bars <EXCHANGE:SYMBOL>` is the bounded Desktop-free historical bars read.
It should be usable without `TV_EXPERIMENTAL_BARS=1`, but it must keep a clear
source boundary:

- source: `tradingview_bars_ws`;
- contract: `bars.v1`;
- source category: `desktop_free_read`;
- no TradingView Desktop or CDP target required;
- no realtime or entitlement guarantee.

`tv bars` is not `tv ohlcv`: `tv ohlcv` reads the selected Desktop chart
through CDP. `tv bars` is symbol-targeted and browserless. It is also not a
streaming feed, watch command, chart-backed compare, scanner quote, or
quote-data source.

## Lane 5: Deferred and later candidates

The following remain deferred unless a separate plan changes the boundary:

- quote-data auto fallback;
- automatic source mixing;
- chart-backed compare;
- watch or JSONL compare;
- realtime multi-symbol feed;
- standalone `tv events`;
- binary split;
- MCP server work;
- daemon, dashboard, or trading-bot behavior;
- ranking, scoring, or buy/sell recommendations.
