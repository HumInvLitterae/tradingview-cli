# v0.13.0 roadmap draft

This document records the `v0.13.0` direction after the `v0.12.0` release.

Status as of 2026-05-08: `v0.12.0` has been released. The `tv compare
<SYMBOL>...` contract now exposes coverage status and missing-evidence
readback for downstream routing. The next risk is not a missing ranking or
recommendation feature; it is agents mistaking one source/session boundary for
another.

## Theme

`v0.13.0` is about source and session boundary clarity for agent workflows.

The goal is to keep Desktop-free reads, chart-source reads, chart observation,
and screenshots distinct enough that agents do not infer extended-hours,
freshness, or visual evidence from the wrong command.

## Lane 1: Chart Quote Session Boundary

The first implementation slice should focus on
`tv quote <SYMBOL> --source chart`.

Current chart-source quote reads the selected TradingView Desktop chart's
main-series bars and chart symbol metadata. It now reports additive
`session_boundary` metadata so agents can see that scanner-backed
`extended_hours.premarket` and `extended_hours.postmarket` values are not
included or guaranteed by this source.

The first slice should investigate whether chart-source quote can safely expose
premarket or postmarket values from chart API, main-series bars, `symbolExt`,
or visible session settings. If stable evidence exists, design additive
metadata. If not, make the boundary explicit so agents know that chart-source
quote does not guarantee extended-hours evidence and should use scanner-backed
quote, `snapshot`, `quotes`, or `compare` when premarket/postmarket fields are
needed.

That first boundary slice is complete: chart-source quote now reports additive
`session_boundary` metadata that says the selected chart main-series last bar
does not include or guarantee scanner-style extended-hours values.

Follow-up live probing found a separate Desktop page quote session through
`window.getQuoteSessionInstance()`. It can return field names such as
`premarket_close`, `postmarket_close`, `session-premarket`,
`session-postmarket`, and `market-status`. During regular session, those
pre/post fields did not behave like scanner-backed premarket values; they
looked closer to streaming current-session values. Therefore the next slice
adds an opt-in live smoke for postmarket and premarket evidence instead of
exposing those fields immediately.

The first attempted postmarket smoke reached the quote-session probe but still
observed regular-session behavior for the tested U.S. symbol. That run is not
accepted as postmarket evidence. The current decision remains conservative:
collect phase-specific evidence later, and do not expose Desktop quote-session
pre/post fields as public payload values until their session semantics are
clear.

The smoke now treats a phase mismatch as `not_yet_in_expected_phase` rather
than as a failed evidence run. Regular-session re-runs should not move the
roadmap decision forward; the next meaningful decision still requires
postmarket or premarket live evidence from the matching session.

Postmarket evidence is now partially collected. During a real postmarket window
for a selected-chart `BATS:MU` probe, Desktop quote session reported
`market-status.phase` as `post-market` with streaming values, while scanner
REST remained delayed and did not return a postmarket close. This confirms
that Desktop quote session can expose a postmarket phase, but it does not prove
that `premarket_*` or `postmarket_*` fields are scanner-style
`extended_hours` values because the selected pre/post close fields matched
each other and remained tied to quote-session streaming values in the
public-safe summary.

The live smoke now treats `post-market` as the same expected phase as
`postmarket`, and `pre-market` as the same expected phase as `premarket`.
Premarket evidence remains open until the same probe is run during a real
premarket window.

RKLB provided a clearer postmarket divergence. Scanner REST returned delayed
`extended_hours.postmarket` data, chart main-series quote and the current
quote-session selected field set returned the regular close-like value, while
the visible TradingView Desktop right-side detail panel displayed a separate
after-market price. The current slice adds an ignored live smoke to capture
scanner, chart main-series, quote-session, and visible panel summaries in one
public-safe run. This is source discovery only; `tv quote --source chart`
payload support is not changed.

Do not automatically mix scanner extended-hours values or Desktop quote-session
fields into a chart-source payload. If a future command combines sources, it
must label each source explicitly. Postmarket and premarket support should be
considered only after session-phase live evidence shows stable semantics.

## Lane 2: Snapshot Contract Metadata Alignment

After chart-source quote session boundaries are clear, extend the
compare-style evidence vocabulary to `tv snapshot <SYMBOL>`.

Potential additions include a command-local contract marker, coverage status,
field coverage readback, machine-readable missing evidence, and stable
follow-up hints. These should be additive and should not change the existing
snapshot `sections` shape.

`snapshot` remains a one-symbol Desktop-free evidence packet. It should not
become a batch command, a watch/JSONL command, chart-backed read, automatic
screenshot command, or ranking surface.

This lane is now the current implementation slice while Lane 1 waits for
postmarket or premarket timing. Snapshot metadata should be additive:
`contract_version: "snapshot.v1"`, coverage summary, missing-evidence
readback, and machine-readable follow-up hints. Raw `sections` remain the
evidence source.

This lane is complete: `tv snapshot <SYMBOL>` now exposes additive
`snapshot.v1` contract metadata, coverage summary, missing-evidence readback,
and machine-readable follow-up hints while preserving the raw `sections`
evidence.

## Lane 3: Cross-command Follow-up Vocabulary

Keep follow-up vocabulary consistent across commands where useful:

- `snapshot`: one-symbol Desktop-free detail;
- `chart_quote`: selected-chart single-symbol quote follow-up;
- `observe_chart`: selected-chart time-window observation;
- `screenshot`: visual evidence when structured reads are insufficient.

This lane should align docs and additive metadata without breaking the
`compare` contract shipped in v0.11 and v0.12.

This is now the current implementation slice. The work should lock the shipped
vocabulary as stable contract values, document that `chart_quote` is the
canonical value rather than `quote_chart`, and avoid changing existing JSON
payload shape.

This lane is complete: `compare` and `snapshot` now share documented stable
follow-up vocabulary, focused tests reject the unshipped `quote_chart` alias,
and runtime skills describe the hints as evidence surfaces rather than
recommendations or automatic reads.

## Pre-release Audit

`v0.13.0` has reached pre-release audit. No new feature work should be added
before release readiness. The audit should confirm that chart-source quote
session-boundary metadata, Desktop quote-session smoke timing guard, snapshot
contract metadata, and follow-up vocabulary alignment match implementation,
tests, docs, and runtime skills.

Postmarket and premarket quote-session payload support remains phase-specific
evidence work. It should not block the release if the shipped v0.13 state is
clearly documented as evidence tooling and timing guard only.

The pre-release audit found no blocker before this postmarket follow-up. The
postmarket evidence should be recorded before release readiness, while
phase-specific payload support remains deferred until the quote-session field
semantics are better understood and premarket evidence is collected.

The postmarket follow-up found an additional source boundary: Desktop visible
panel after-hours price can differ from scanner REST, chart main-series quote,
and the current quote-session selected fields. Record that evidence before
release readiness; do not promote it to public payload support without a
separate design.

The follow-up source discovery now narrows that visible RKLB after-hours value
to the TradingView right-side detail widget status block and price node. React
metadata was present on the matched node, but this remains a visible UI source,
not a stable TradingView data API. A later slice may either keep searching for
the backing store behind that widget or design an explicitly labeled
visible-panel evidence read. It should not be silently merged into
`quote --source chart`.

The next source-discovery slice goes one level lower by observing CDP Network
and WebSocket events during a bounded opt-in smoke. The goal is to learn
whether any communication event can be tied to the visible after-hours value
without recording raw frames or changing public quote payloads.

The Network/WebSocket smoke is now in place and was run against RKLB while the
visible panel still showed the expected after-hours price. It observed
symbol-related WebSocket traffic, but no captured candidate contained the
visible after-hours price token. The lowest identified source therefore
remains the right-side detail widget status/price node. Public payload support
remains deferred until a less brittle source is identified or a separate
visible-panel evidence contract is designed.

The current source-discovery slice inspects the matched right-side detail
widget's React fiber chain, props, and state to see whether the visible value
can be tied to an in-page component or store candidate. This remains
research-only and must not expose raw props or state.

The widget-store smoke is now in place. A screenshot-backed RKLB postmarket
rerun confirmed a separate right-side visible after-market price. Scoped React
inspection around that widget exposed regular quote-like props, including
`data.quotes.last_price` and `data.quotes.current_session=post_market`, but it
did not expose the visible after-market price token in the compact prop/state
hits. The lowest identified source for that after-market value remains visible
right-panel DOM evidence, and a stable in-page store or communication source
remains unconfirmed.

Because the right-side value updates like push data and repeated deep DOM
inspection may leave the panel in an abnormal visible state, the current slice
returns to WebSocket evidence with a narrower method: bounded CDP WebSocket
capture plus minimal right-side visible price samples. It avoids
quote-session subscription and broad DOM/store scans. The goal is correlation
evidence only, not public payload support.

That correlation smoke produced the strongest postmarket evidence so far. In a
screenshot-backed RKLB run, the right-side visible after-market price changed
during the bounded capture window, and each sampled visible after-market price
appeared as an exact numeric candidate in received WebSocket frames. This
supports a WebSocket-backed or push-fed source hypothesis, but it still does
not identify a stable field name or payload schema. Public payload support
remains deferred.

Follow-up HAR and live evidence narrowed the candidate further. Web TradingView
WebSocket traffic contains `qsd` quote-data messages with fields such as `lp`,
`regular_close`, `rtc`, `rtc_time`, `rch`, `rchp`, and `current_session`.
During a bounded RKLB postmarket run, visible after-market samples changed from
the initial visible value to later values, and RKLB `qsd.rtc` candidates
matched those later visible samples. This makes `qsd.rtc` the strongest
current backing-source candidate for the right-side after-market display.
Because this is still an internal WebSocket quote-data stream, v0.13 keeps it
as source-discovery evidence and does not add public quote payload support.

The next slice is source-design rather than payload implementation. It should
decide whether `qsd.rtc` can become an explicitly labeled Desktop-backed
quote-data source, for example `tv quote <SYMBOL> --source quote-data`, while
preserving the existing boundaries: do not mix `qsd.rtc` into
`quote --source chart`, and do not merge it with scanner REST
`extended_hours`. Any future payload should label its source as a WebSocket
quote-data readback and should expose `rtc`, `rtc_time`, `rch`, `rchp`,
`current_session`, `market_phase`, and `update_mode` without claiming full
scanner-style regular/premarket/postmarket semantics.

That source-design slice is complete, and the current implementation slice
adds the explicit source. `tv quote <SYMBOL> --source quote-data` should read
bounded Desktop-backed WebSocket quote-data messages and expose `qsd.rtc`
readback under a separate `desktop_quote_data_ws` source. It must not change
`--source chart`, must not join `--source auto`, and must not synthesize
scanner-style `extended_hours`.

The quote-data source implementation is complete. The current slice adds an
opt-in ignored live contract smoke so a real TradingView Desktop page can
confirm either a public-safe `qsd.rtc` success payload or a public-safe
structured unavailable result when no matching frame arrives during the
bounded window. Because after-hours has ended for the current run, unavailable
is an accepted contract result by default rather than a release blocker.

## Lane 4: Deferred Work

The following remain deferred unless a separate plan changes the boundary:

- ranking, scoring, or buy/sell recommendations;
- chart-backed compare;
- watch or JSONL compare;
- realtime multi-symbol feed;
- stable browserless bars;
- standalone `tv events`;
- `tv diagnose`;
- `tvb`, `tvd`, or other alternate binaries;
- MCP server work;
- daemon, dashboard, or trading-bot behavior;
- cookie/session import or export;
- raw TradingView endpoint primitives;
- public-stable crates.io publication promises;
- downstream-specific artifact output.
