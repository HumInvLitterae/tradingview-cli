# v0.13.0 roadmap draft

This document records the `v0.13.0` direction after the `v0.12.0` release.

Status as of 2026-05-08: `v0.12.0` has been released. The `tv compare
<SYMBOL>...` contract now exposes coverage status and missing-evidence
readback for downstream routing. The next risk is not a missing ranking or
recommendation feature; it is agents mistaking one source/session boundary for
another.

## Theme

`v0.13.0` is about source and session boundary clarity for agent workflows.

The goal is to keep Desktop-free reads, chart-source reads, chart observation,
and screenshots distinct enough that agents do not infer extended-hours,
freshness, or visual evidence from the wrong command.

## Lane 1: Chart Quote Session Boundary

The first implementation slice should focus on
`tv quote <SYMBOL> --source chart`.

Current chart-source quote reads the selected TradingView Desktop chart's
main-series bars and chart symbol metadata. It now reports additive
`session_boundary` metadata so agents can see that scanner-backed
`extended_hours.premarket` and `extended_hours.postmarket` values are not
included or guaranteed by this source.

The first slice should investigate whether chart-source quote can safely expose
premarket or postmarket values from chart API, main-series bars, `symbolExt`,
or visible session settings. If stable evidence exists, design additive
metadata. If not, make the boundary explicit so agents know that chart-source
quote does not guarantee extended-hours evidence and should use scanner-backed
quote, `snapshot`, `quotes`, or `compare` when premarket/postmarket fields are
needed.

Do not automatically mix scanner extended-hours values into a chart-source
payload. If a future command combines sources, it must label each source
explicitly. The first v0.13 slice is complete when this boundary is covered by
payload metadata, tests, docs, and runtime skills.

## Lane 2: Snapshot Contract Metadata Alignment

After chart-source quote session boundaries are clear, extend the
compare-style evidence vocabulary to `tv snapshot <SYMBOL>`.

Potential additions include a command-local contract marker, coverage status,
field coverage readback, machine-readable missing evidence, and stable
follow-up hints. These should be additive and should not change the existing
snapshot `sections` shape.

`snapshot` remains a one-symbol Desktop-free evidence packet. It should not
become a batch command, a watch/JSONL command, chart-backed read, automatic
screenshot command, or ranking surface.

## Lane 3: Cross-command Follow-up Vocabulary

Keep follow-up vocabulary consistent across commands where useful:

- `snapshot`: one-symbol Desktop-free detail;
- `chart_quote`: selected-chart single-symbol quote follow-up;
- `observe_chart`: selected-chart time-window observation;
- `screenshot`: visual evidence when structured reads are insufficient.

This lane should align docs and additive metadata without breaking the
`compare` contract shipped in v0.11 and v0.12.

## Lane 4: Deferred Work

The following remain deferred unless a separate plan changes the boundary:

- ranking, scoring, or buy/sell recommendations;
- chart-backed compare;
- watch or JSONL compare;
- realtime multi-symbol feed;
- stable browserless bars;
- standalone `tv events`;
- `tv diagnose`;
- `tvb`, `tvd`, or other alternate binaries;
- MCP server work;
- daemon, dashboard, or trading-bot behavior;
- cookie/session import or export;
- raw TradingView endpoint primitives;
- public-stable crates.io publication promises;
- downstream-specific artifact output.

## Current ExecPlan

- `docs/plans/tradingview-cli-chart-quote-session-boundary.md`

The current slice implements additive chart-source quote session-boundary
metadata and docs / skill guidance. It keeps extended-hours values on scanner
sources and does not merge them into chart-source quote payloads.
