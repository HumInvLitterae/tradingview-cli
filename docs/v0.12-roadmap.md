# v0.12.0 roadmap draft

This document records the `v0.12.0` direction after the `v0.11.0` release.

Status as of 2026-05-08: `v0.11.0` has been released. The `tv compare
<SYMBOL>...` payload now includes a command-local `contract_version`,
requested-order indexes, per-item `follow_up_hints`, and
`summary.field_coverage`. The current phase is v0.12 roadmap planning and the
first follow-up contract ExecPlan.

Downstream feedback after `v0.11.0` says the highest-value next work is still
not a new data source. It is making `compare` output safer to join, summarize,
and route into explicit follow-up evidence commands.

## Theme

`v0.12.0` is about contract-stable evidence follow-up.

The goal is to keep `compare` as a Desktop-free multi-symbol evidence packet
while making its coverage and follow-up metadata stable enough for downstream
agents to consume without guessing.

## Lane 1: Compare Follow-up Contract

`tv compare <SYMBOL>...` should document and test the machine-readable
metadata added in `v0.11.0`.

The leading implementation candidate is follow-up and coverage contract
polish:

- fix the stable `follow_up_hints[].kind` value list as a public contract;
- document `summary.field_coverage` count semantics;
- document `requested_index` as the join authority between requested symbols,
  `items[]`, and `summary.resolved_symbols[]`;
- add a thin `summary.coverage_status` readback such as `complete`, `partial`,
  or `blocked`;
- ensure structured compare failure details retain `contract_version:
  "compare.v1"` and the same readback contract.

These fields remain readback only. They must not rank symbols, score
securities, recommend trades, or imply operator action.

## Lane 2: Item-level Missing Evidence

After the contract vocabulary and count semantics are stable, the next useful
polish is item-level missing evidence.

Potential additive metadata should be derived from existing quote, info, and
fundamentals sections. It can expose missing fields, missing reasons, suggested
follow-up surfaces, and whether a suggested follow-up requires TradingView
Desktop. It should not add new network reads or infer financial meaning from
missing values.

This lane should stay smaller than a new feature surface. The first v0.12
implementation should prefer stabilizing existing `missing_summary` and
`field_coverage` before adding a larger schema.

## Lane 3: Cross-command Vocabulary Alignment

`snapshot`, `quote --source chart`, `observe chart`, and `screenshot` should
eventually use the same follow-up vocabulary where that helps downstream
agents.

The boundary remains source-specific:

- `tv compare <SYMBOL>...` for Desktop-free multi-symbol evidence coverage;
- `tv snapshot <SYMBOL>` for one-symbol Desktop-free detail;
- `tv observe chart --duration-ms ...` for selected-chart time-window
  observation;
- `tv quote <SYMBOL> --source chart` for single-symbol chart-feed follow-up;
- `tv screenshot` for visual evidence after structured reads are insufficient.

Do not fold chart observation, screenshot capture, or chart-source quote into
`compare` by default.

## Lane 4: Deferred Work

The following remain deferred unless a separate plan changes the boundary:

- ranking, scoring, or buy/sell recommendations;
- chart-backed compare;
- watch or JSONL compare;
- realtime multi-symbol feed;
- stable browserless bars;
- standalone `tv events`;
- `tv diagnose`;
- `tvb`, `tvd`, or other alternate binaries;
- MCP server work;
- daemon, dashboard, or trading-bot behavior;
- cookie/session import or export;
- raw TradingView endpoint primitives;
- public-stable crates.io publication promises;
- downstream-specific artifact output.

Chart-source quote remains a correctness-first single-symbol follow-up source.
If the rare mismatch issue reappears, handle it in a patch lane separate from
`compare` follow-up contract polish.

## Current ExecPlan

- `docs/plans/tradingview-cli-compare-follow-up-contract.md`

The current slice records the first v0.12 implementation plan: stabilize
`compare` follow-up vocabulary, field coverage semantics, requested-order join
rules, coverage status readback, and failure-side contract guards without
adding new sources or recommendations.
