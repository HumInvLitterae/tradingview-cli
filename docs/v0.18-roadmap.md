# v0.18.0 roadmap draft

This document records the `v0.18.0` direction after the `v0.17.0` release.

Status as of 2026-05-17: the pre-release audit is complete and no release
blocker was found.
`v0.17.0` is treated as released.

## Theme

`v0.18.0` is about JSONL observation contract maturity and source workflow
clarity.

The goal is not to add realtime multi-symbol feeds, watch loops, source
mixing, or trading recommendations. The goal is to make the existing bounded
Desktop-backed JSONL observation surfaces easier for agents and downstream
tools to read safely: `tv observe chart` and lower-level `tv stream ...`
should have clear event metadata, readiness / sample / heartbeat semantics,
and source boundaries.

## Lane 1: `tv observe chart` contract maturity

Status: complete for the first `v0.18.0` slice.

`tv observe chart` should remain a selected-chart Desktop-backed observation
workflow. It emits readiness first, then selected-chart bar samples and
heartbeats within a bounded window.

The first implementation lane should stabilize this as a JSONL event contract:

- keep readiness, sample, and heartbeat events;
- add additive command-local contract metadata;
- keep selected-chart source metadata readable on every non-error event;
- keep `tv observe chart` non-mutating;
- do not switch symbols, activate tabs, capture screenshots, or read
  browserless bars.

## Lane 2: Lower-level `tv stream ...` contract clarity

Status: complete for the first `v0.18.0` slice.

`tv stream ...` should remain the lower-level selected-chart sample surface for
specific chart/page sample types such as quote or bars. Its JSONL events
already include source metadata and `_event` / `_stream` markers; v0.18 should
make these event contracts consistent with `observe chart` without changing
their meaning.

This lane does not promote `tv stream ...` into a multi-symbol realtime feed,
watch loop, or browserless historical bars source.

## Lane 3: Source choice workflow clarity

Status: complete for the first `v0.18.0` slice.

JSONL observation workflows should remain source-aware:

- `tv bars` is Desktop-free, symbol-targeted, bounded historical OHLCV;
- `tv ohlcv` is selected-chart CDP bars;
- scanner-backed `tv quote` / `tv quotes` are Desktop-free quote reads that
  can be delayed;
- `quote-data` is explicit Desktop-backed WebSocket quote-data readback;
- `tv observe chart` and `tv stream ...` are selected Desktop chart bounded
  JSONL observations.

Docs and runtime skills should guide agents to read event kind, source
metadata, readiness, sample counts, and heartbeat counts before treating JSONL
lines as market evidence.

## Lane 4: Deferred and later candidates

The following remain deferred unless a separate plan changes the boundary:

- realtime multi-symbol feed;
- watch or JSONL compare;
- chart-backed compare;
- quote-data auto fallback;
- automatic source mixing;
- standalone `tv events`;
- binary split;
- MCP server work;
- daemon, dashboard, or trading-bot behavior;
- ranking, scoring, or buy/sell recommendations.
