# v0.27.0 ordered work inventory

This document is the durable inventory for the `v0.27.0` roadmap. It records
more work than should be active at once so later candidates are not lost when
the repository keeps only one current ExecPlan.

The order is intentional. Promote one item into a self-contained ExecPlan only
after the preceding required item is implemented, validated, reviewed, and
archived. A discovery may reorder later work, but the roadmap, this inventory,
the plan index, and `CONTINUITY.md` must then be updated together.

## Global rules

The workspace version remains `0.26.0` until release readiness. New commands,
options, and payload fields are additive unless an independently reviewed plan
justifies a breaking change. Desktop-free and Desktop-backed sources stay
separate. Chart mutation, panel mutation, file creation, and account-linked
persistence must be explicit in help text and payload metadata.

Do not add automatic source mixing, automatic fallback, ranking, scoring,
recommendation, or trading judgment. Never persist raw live payloads, raw
Strategy Tester report data, raw DOM, credentials, session IDs, target IDs,
account-local identifiers, or machine-specific absolute paths in tracked
files. Live evidence should contain only bounded public-safe summaries.

## Promotion and handback

When promoting an item, create a fresh self-contained ExecPlan with verified
current facts, explicit user-visible outcome, mutation and source boundaries,
focused tests, full baseline, live-smoke requirements, stop conditions, and
docs/skill updates. Do not copy unverified upstream behavior into the Rust CLI.

Implementation handback must state behavior changes, changed files, focused
and full validation, live evidence status, residual risk, source and mutation
semantics, docs/skill synchronization, and worktree state. This inventory never
authorizes a push or other external mutation.
