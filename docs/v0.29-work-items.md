# v0.29.0 ordered work inventory

This inventory turns `docs/v0.29-roadmap.md` into an explicit execution order.
An item may start only after its prerequisite gate is complete and the current
plan index is updated. Placement in this file does not authorize live mutation,
new dependencies, or remote operations.

## Global rules

- Measurement precedes retry and structural optimization.
- Retry before CDP method dispatch is distinct from re-running an operation
  after a method may have executed.
- Mutation and unknown-outcome paths never retry automatically.
- Every retry, wait, probe, and process lifetime has one deterministic absolute
  bound.
- Internal diagnostics require an explicit public-safe mapping before appearing
  in JSON output.
- Do not expose raw target IDs, WebSocket URLs, Runtime payloads, credentials,
  account-local metadata, or machine-specific paths.
- Do not introduce hidden transport fallback, automatic source mixing,
  ranking, recommendation, or trading decisions.
- Each implementation slice gets a self-contained ExecPlan and focused review.
- Keep related commits small and do not push without explicit owner direction.

## Gated future candidates

Shared connection is not an ordered v0.29 implementation item. Measurement may
later justify a feasibility comparison among a foreground bounded session, an
explicit bounded-lifetime broker, and no shared mode. Broker feasibility first
requires an explicit policy decision because it is a background service.

Bounded named waits, operation-specific input preconditions, public recovery
metadata, method-post-dispatch read restart, finite-`f64` right-offset
restoration, width-derived drawing geometry, and Windows MSIX launch each need
separate promotion and plans.
