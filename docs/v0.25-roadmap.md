# v0.25.0 roadmap draft

This document records the `v0.25.0` direction after the `v0.24.0` release.

Status as of 2026-06-11: `v0.24.0` is treated as released. `tv chart
compare`, `tv events compare`, `tv replay log --attach-ohlcv-summary`, and
`tv screenshot --region strategy` have completed their `v0.25.0`
implementation slices. The current work is pre-release architecture audit
before `v0.25.0` release readiness.

## Theme

`v0.25.0` is about chart-backed workflow maturity.

`v0.24.0` made existing operator and symbol-input workflows harder to misuse.
The next release should make selected TradingView Desktop chart evidence more
useful without blurring it with Desktop-free scanner, bars, or event sources.
The main candidate is chart-backed compare: a source-separated workflow for
checking a small set of symbols through selected-chart evidence.

This release should also keep two adjacent workflow tracks visible:
`tv events` expansion and explicit Replay evidence attachment. Both are useful,
but neither should become automatic source mixing, ranking, or a trading
recommendation engine.

## Lane 1: Chart-backed compare command

Status: complete for the first `v0.25.0` implementation slice.

Existing `tv compare` and `tv watch compare` are Desktop-free scanner-backed
compare workflows. They should remain that way. Chart-backed compare should be
a separate Desktop-backed workflow because it depends on TradingView Desktop
state such as the selected chart, target selection, chart switching, symbol
resolution, and possibly restoration after mutation.

The preferred command shape is `tv chart compare <SYMBOL>...`. This keeps the
Desktop-backed workflow visibly separate from `tv compare <SYMBOL>...`.
Adding `tv compare --source chart` is not the initial candidate because it
would make the Desktop-free compare command look like it can silently change
source behavior.

The first implementation adds `tv chart compare <SYMBOL>...` with a narrow
`chart_compare.v1` contract. The output distinguishes requested symbols,
reports selected chart context, keeps ordered per-symbol read status, includes
source metadata, explains that the command may temporarily change chart state,
and reports restore readback. It does not call `tv bars`, scanner compare,
Replay, chart export, quote-data, or other sources as hidden fallbacks.

## Lane 2: `tv events` expansion

Status: complete for the `events_compare.v1` multi-symbol readback slice.

`tv events <SYMBOL>` shapes scanner-backed fundamentals fields into
symbol-scoped earnings / dividends readback. `tv events compare <SYMBOL>...`
now extends that readback to a small ordered candidate set with
`events_compare.v1`.

This is useful but still not a full event calendar. Future event work can
decide whether event ranges, additional event types, or a distinct calendar
source can be represented without pretending that scanner fields are more
precise than they are.

Future event work should keep `events.v1` source metadata clear, report
availability and missing fields explicitly, and avoid inferring timezone,
session timing, confirmation status, ranking, recommendations, or trading
judgment when the source does not say those things.

## Lane 3: Replay evidence attachment

Status: complete for the OHLCV summary attachment slice.

`tv replay log --steps <N>` records bounded Replay step evidence as JSONL.
The first attachment slice adds `--attach-ohlcv-summary` and `--ohlcv-count
<N>` so callers can explicitly attach selected-chart OHLCV summary evidence
after each successful Replay step. The attachment uses its own
`replay_log_ohlcv_summary_attachment.v1` metadata and reports attachment
errors separately from Replay step failures.

Screenshot attachment remains a future candidate because it needs explicit
file path, naming, and artifact lifecycle semantics before implementation.

Replay evidence remains Desktop-backed selected-chart workflow evidence. It is
not a replacement for reproducible Desktop-free historical bars from
`tv bars --from/--to`, and it should not automatically mix with chart export,
scanner compare, or event reads.

## Lane 4: Remaining usability / workflow polish

Status: Strategy Tester screenshot evidence is complete for `v0.25.0`.

`tv screenshot --region strategy --output <PATH>` is the first narrow polish
item in this lane. It provides visual evidence for the visible Strategy Tester
panel while keeping structured strategy data in `tv data strategy`, `tv data
trades`, and `tv data equity`.

The following remain useful but lower priority:

- remaining intraday `tv bars --from/--to` timeframes such as `1`, `3`, `45`,
  `120`, `180`, and `240`;
- richer strategy-report evidence beyond panel screenshots;
- Screener columns reset / cleanup workflow;
- Pine new-script save workflow.

Each item needs its own source boundary and acceptance criteria before it
becomes a stable command or option.

## Lane 5: Deferred and later candidates

The following remain deferred unless a separate plan changes the boundary:

- quote-data auto fallback;
- automatic source mixing;
- daemon, dashboard, or trading-bot behavior;
- MCP server work;
- binary split;
- ranking, scoring, or buy/sell recommendations.

These change the operating model more than chart-backed evidence workflows and
should not be folded into `v0.25.0` by accident.

## Current Plan

- `docs/plans/tradingview-cli-v0.25-pre-release-audit.md`

The current slice audits completed `v0.25.0` chart-backed workflow maturity
before release readiness. It confirms the source boundaries, docs, runtime
skills, tests, and architecture posture for chart-backed compare, events
compare, Replay OHLCV summary attachment, and Strategy Tester screenshot
evidence.

Audit conclusion: no release-blocking architecture issue and no larger
refactor requirement were found. The next step is `v0.25.0 release readiness`.
