# v0.27.0 roadmap

This document records the direction after the `v0.26.0` release.

Status as of 2026-07-13: `v0.26.0` is released from commit `5e7f48f` and the
workspace version remains `0.26.0`. The promoted v0.27 feature slices through
R11 are implemented, validated, and independently reviewed. R12 documentation
and runtime-skill consolidation is complete. R13 completion and architecture
audit planning is active; release readiness has not started.

The detailed ordered inventory and retained backlog live in
`docs/v0.27-work-items.md`. Only the first item has a full ExecPlan. Later items
must be promoted one at a time after the preceding item is green.

## Theme

`v0.27.0` is about current-build chart and evidence workflow correctness.

The v0.26 release strengthened process, transport, timeout, and concurrency
boundaries. The next release should use that foundation to make Desktop-backed
reads more dependable against current TradingView Desktop behavior and to make
evidence easier to identify correctly. Existing commands come first: a
Strategy Tester read that silently selects the wrong study is more harmful than
a missing convenience command.

This release may also add carefully bounded discovery and evidence features,
but it does not change the project's source model. Desktop-free reads,
selected-chart reads, chart mutations, Replay operations, and screenshots
remain explicit surfaces. No command automatically mixes them or converts
their evidence into ranking, recommendation, or trading judgment.

## Lane 1: Strategy Tester current-build compatibility

Priority: highest. Status: complete. Archived ExecPlan:
`docs/plans/archives/tradingview-cli-strategy-tester-compatibility.md`.

The existing `tv data strategy`, `tv data trades`, and `tv data equity`
commands now identify current strategy metadata through `StrategyScript`,
`isTVScriptStrategy`, or `is_strategy`, reject the false-positive-prone legacy
price-study heuristic, and select report-bearing candidates without chart-order
dependence. Shared public-safe context explains hidden, unready, missing, and
ambiguous states without opening the panel or changing visibility.

The completed bounded matrix covered visible, hidden, panel-open,
panel-closed, and no-strategy states on an isolated test layout. A safe exact
second strategy fixture was unavailable, so multiple-strategy live evidence
remains explicitly unconfirmed while deterministic ambiguity fixtures cover
the selection rule.

The implementation preserved the three existing commands and practical
fields. It does not open Strategy Tester or change study visibility; hidden or
unready state produces a structured next action instead.

## Lane 2: Indicator and strategy discovery

Priority: high after Lane 1.

The current `tv indicator add` calls the chart's `createStudy` interface using
a name supplied by the caller. That works for many built-in studies but does
not provide a discoverable path for built-in strategies, Community scripts, or
saved scripts shown by TradingView's Indicators dialog.

Split discovery from mutation. R5 established the provisional read-only search
contract, but bounded current-build inventory did not expose trustworthy
result-row, loading, or explicit-empty semantics. The next slice is therefore
a stop/go parser-feasibility spike, not command implementation. It adds no
public API and may proceed to implementation only after semantic result and
empty-state anchors plus restoration are proven.

If feasibility is green, a later R6b may add a search surface that returns
normalized title, section, script kind, and author or source label when
available. A zero-based result index is response-local only. No reusable opaque
selection key is promised unless feasibility independently proves a stable,
public-safe identity. Search must expose ambiguity rather than choosing the
first partial match.

A later exact-add slice may add one chosen result. It must require exact title
and section or another unambiguous selector, compare study identities before
and after the operation, return the new entity ID, and fail if more than one
study appears or the result cannot be verified. Search and add should remain
under the existing indicator domain rather than becoming broad generic UI
automation.

## Lane 3: Visible-range history paging

Priority: high after indicator discovery, or earlier if Strategy Tester work
demonstrates that range correctness blocks validation.

R8 and R9 are complete and independently reviewed after the indicator-search
implementation trial was deferred. Bounded selected-chart paging, explicit
progress and stopping reasons, additive coverage and viewport diagnostics,
pre-connection validation, and deterministic deadline/failure fixtures are
implemented and green.

`tv range --from --to` now pages the selected chart's main-series history
before moving the visible bar range. It stops when the requested start is
covered, history is exhausted, no progress is observed, the absolute deadline
expires, or the request limit is reached. It does not use `tv bars`, Replay,
export, or another source as a fallback.

The result reports requested range, earliest loaded time before and after,
request count, terminal reason, coverage status, viewport application, and
actual visible range. This is a correctness improvement to an explicit
Desktop-backed viewport operation, not automatic historical export.

## Lane 4: Evidence fidelity

Priority: medium, suitable for two small independent slices.

R10 screenshot render-ready waiting and R11 study-value identity are
implemented, fully validated, and independently reviewed green. R12 confirmed
that feature details remain routed through focused references rather than
expanding skill Core Workflow sections.

The screenshot slice should add an opt-in render-ready wait for captures made
soon after symbol, timeframe, range, or panel changes. Readiness must be
bounded and observable: report the timeout, elapsed wait, last observed symbol
and resolution, canvas dimensions, and ready or timeout outcome. A timeout
must not be presented as a stable rendered screenshot.

The study-value slice should make same-name studies distinguishable. Each
`tv values` row should add the chart entity ID, short name, public-safe study
kind, compact inputs, and visibility where available while preserving the
existing name and values. This is additive evidence identity, not a change to
indicator calculations.

## Lane 5: Operational convenience candidates

Priority: lower and capacity dependent.

A read-only `tv update check` is a reasonable packaging improvement. It should
compare the running binary version with the latest stable GitHub Release,
report whether an exact platform asset exists, and provide the release URL.
Failure to check for updates must not make unrelated commands fail. Binary
self-update is a separate security and platform-replacement problem and is not
part of the initial candidate.

Opening a saved layout in a new Desktop tab and creating a named layout remain
feasibility work. Existing `tv tab new` and `tv layout switch` cover parts of
the workflow, while named layout creation changes account-linked state and
depends on landing-page target replacement. If promoted, exact matching,
target handoff, dry-run or confirmation, and mutation recovery must be planned
before implementation.

## Retained backlog

The upstream review does not erase earlier product work. The detailed inventory
retains bounded event ranges and source availability, Replay screenshot
attachments, remaining intraday bars ranges, Screener column reset, and safe
new Pine script naming and save. Strategy Tester compatibility supersedes the
older broad "richer evidence" priority because correctness of existing
structured reads must come first.

A complete economic calendar, automatic Replay export, automatic historical
export expansion, broad generic UI automation, self-update, and account-state
layout creation require separate feasibility or security plans before they can
enter a release.

## Deferred boundaries

The following remain unscheduled unless a later roadmap explicitly changes the
project model:

- automatic quote-data fallback;
- automatic mixing of scanner, bars, selected-chart, Replay, event, or
  screenshot evidence;
- cookie or session import, login automation, and trading bots;
- daemon, dashboard, MCP server, or binary split work;
- ranking, scoring, or buy/sell recommendations;
- generic UI control unrelated to a named TradingView workflow.

## Validation posture

Each implementation slice starts with deterministic focused tests and then the
normal workspace baseline:

    cargo fmt --check
    cargo clippy --workspace --all-targets --all-features -- -D warnings
    cargo test --workspace
    cargo metadata --no-deps --format-version 1
    git diff --check
    bash -n scripts/stage-release-package-files.sh

Desktop and network smokes are supplemental except when a compatibility claim
cannot be established locally. A required live matrix must use bounded
operations and public-safe summaries. Tracked files must never contain raw live
payloads, raw bars, raw report data, credentials, session identifiers,
account-local identifiers, raw target identifiers, or machine-specific
absolute paths.

Feature completion includes help, README or stable workflow docs, packaged
agent guidance, and the relevant runtime skills. Skill updates should route to
small references when a core workflow would otherwise become overloaded.
