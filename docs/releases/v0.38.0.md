`v0.38.0` adds protocol progress to MCP read errors and updates dependencies.
It helps distinguish a stalled initialization or tool catalog from a tool request
waiting for a response.

## Inspect MCP read progress

Read errors with `code:"deadline_exceeded"` or `code:"transport_error"` at
`stage:"tool_response"` can include `error.details.protocol`. Each observed
method has a phase and an HTTP status. For example, this error-details fragment
shows that initialization completed and the tool catalog is waiting for headers:

```json
{
  "code": "deadline_exceeded",
  "stage": "tool_response",
  "tool_attempts": 0,
  "automatic_retry": false,
  "protocol": {
    "initialize": {"phase": "json_complete", "status": 200},
    "tools/list": {"phase": "await_headers", "status": null}
  }
}
```

Observations can cover `initialize`, `notifications/initialized`, `tools/list`,
`tools/call`, and `event_stream`. Unobserved methods are omitted. A null status
means response headers have not arrived. JSON body reads and SSE responses have
separate phases. An event stream can overlap another request, so its state alone
does not identify the failed request or its cause.

Existing `mcp_error.v1` fields, exit codes, the default 30-second read deadline,
and the no-automatic-retry policy are unchanged. Tool attempts remain local
attempt counts, not proof of provider acceptance. Successful results,
authentication errors, and account-mutation errors keep their existing shape.
Protocol observations exclude URLs, headers, tokens, session IDs, tool arguments,
raw response bodies, cancellation, and cleanup. Offline `tv spec mcp ...` and
the distributed connection guides describe the new error interpretation.

## Dependency updates and authentication

The release updates rmcp from 3.5.0 to 3.5.1, serde_json from 1.0.151 to 1.0.154,
and keyring-core from 1.0.0 to 1.0.1. It refreshes 19 compatible transitive
dependencies, including the HTTP and cryptography stack, build tooling, and
procedural-macro parser.

The SDK's optional refresh-token rejection callback does not change credential
handling. Existing persisted state prevents a failed refresh from being repeated
by the next command. A regression test confirms that an OAuth `invalid_grant`
requires explicit login, sends no second refresh request, and permits reads
after new authorization. Credentials are not automatically deleted.

## Verification scope

The feature source passed 1,187 Rust tests, full-workspace Clippy, formatting,
and runtime-guide packaging checks on macOS. Synthetic loopback cases cover
stalled initialization, catalog and tool headers, JSON and SSE bodies, concurrent
event streams, disconnected responses, and rejected token refreshes. These tests
verify diagnostic output and request counts without contacting the provider.
The pinned JavaScript contract gates also passed against the updated dependencies.
The implementation and dependency set at `e251e599` passed all 11 CI jobs,
including Linux, macOS, and Windows tests. Release-commit CI and native archive
qualification are separate checks. These fixtures do not establish live provider
health or performance.
