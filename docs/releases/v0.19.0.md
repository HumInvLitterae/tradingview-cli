This release makes `tv bars <EXCHANGE:SYMBOL>` usable for reproducible older
daily sample preparation by adding a Desktop-free date-range readback mode.
The focus is daily historical bars through the existing `bars.v1` source, not
selected-chart viewport export, realtime feeds, source mixing, ranking, or
recommendations.

## Highlights

- Added `tv bars <SYMBOL> --timeframe 1D --from YYYY-MM-DD --to YYYY-MM-DD`
  for daily historical date-range reads.
- Date-range payloads keep the existing `bars.v1` source boundary and add
  `request_mode`, `requested_range`, `returned_range`, `observed_range`, and
  `range_coverage_status`.
- `--to` is an inclusive calendar date. Payloads also expose
  `requested_range.to_time_exclusive` as public-safe readback for the filter
  boundary.
- `--count` remains the recent-count control outside date-range mode. In
  date-range mode it is a safety cap and defaults to 500.

## Behavior Notes

- Date-range mode is initially daily-only. Intraday, weekly, and monthly
  date-range reads remain deferred.
- `tv bars` remains a Desktop-free bounded historical bars read with
  `contract_version: "bars.v1"` and `source: "tradingview_bars_ws"`.
- `tv range` still moves the selected Desktop chart viewport. It is not a
  historical export contract for `tv ohlcv`.
- `tv ohlcv` still reads selected-chart CDP bars and is separate from
  browserless historical `tv bars`.
- Range coverage and source availability fields are source diagnostics. They
  are not price evaluation, ranking, scoring, recommendation, or trading
  action evidence.

## Packaging

Release archives include the `tv` binary, README, changelog, license,
user-facing agent guides, and runtime-oriented skills only. Development-only
skills remain excluded.
