`v0.41.0` adds saved Desktop watchlist inspection, section editing and
reordering, and fixes metadata-only Pine shape reads.

## Inspect saved watchlists

```sh
tv watchlist inspect <LIST_ID>
```

This Desktop-backed read returns the saved list without selecting it. The
`watchlist` object contains `symbols` and ordered `entries`, including section
names and saved collapse state. Collapsed sections retain their members.
Unknown contents are `null`; empty contents are empty arrays. This differs from
`watchlist get`, which reads rendered rows. Official `mcp watchlist get` remains
the Desktop-free option.

## Edit sections and order

The following commands operate on the custom list displayed in the selected
Desktop tab. Use the shared `--target-id <TAB_ID>` option when needed.

```sh
tv watchlist section rename "Candidates" "Review"
tv watchlist section collapse "Review"
tv watchlist section expand "Review"
tv watchlist move "NASDAQ:AAPL" --before "NASDAQ:MSFT"
tv watchlist move "NASDAQ:AAPL" --after "NASDAQ:MSFT"
tv watchlist move "NASDAQ:AAPL" --to-section "Review"
tv watchlist section move "Review" --before "Excluded"
tv watchlist section move "Review" --after "Holdings"
```

No rows may be selected and no display sort may be active. Rename, collapse and
expand require a unique rendered heading. Names are matched exactly.

Moves require exactly one destination and reject duplicate symbols or heading
names anywhere in the list. A symbol must belong to an expanded section or the
unsectioned prefix; its destination section must be expanded. Rows need not be
inside the visible viewport. Moving relative to another section's symbol changes
section membership; `--to-section` appends, including to an empty section.
Whole-section moves preserve internal order and collapse state, including hidden
members. These commands do not move symbols between lists.

Moves replace the complete saved array. A fresh read detects existing changes,
but the provider offers no atomic revision check. Do not edit the same list
elsewhere during a move: successful readback cannot prove that a concurrent edit
was not overwritten.

Changes invoke an existing Desktop handler once and report `write_attempted`,
`changed`, `saved_confirmation` and `display_confirmation`. Success requires
both confirmations to be `matched`. A failed or timed-out operation can already
have changed saved or displayed state; `changed:null` is uncertain, not a
rollback. Inspect state before another operation. There is no automatic retry,
list switch, scrolling, reload, alternate write path or compensating write.
Other tabs may synchronize, but their synchronization is not a success criterion.

## Metadata-only Pine shape reads

`tv data shapes --count 0` now returns metadata without shape points instead of
rejecting zero. Other count validation and source semantics are unchanged.

## Maintenance

Contract gates now fail when no tests are selected. Targeted tests exercise real
execution paths, redundant coverage was removed, and embedded JavaScript was
formatted without changing runtime behavior.

Dependencies include rmcp 3.8.0 and compatible transitive updates. Distribution
targets and archive contents are unchanged.
