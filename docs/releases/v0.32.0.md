`v0.32.0` adds an independent official TradingView MCP client to `tv`, alongside
its existing Desktop, scanner and historical-data commands. It also makes the
packaged agent skills independently attachable and routes suitable tasks toward
MCP without silently changing existing command backends.

## Official MCP commands

Use an eligible paid TradingView account. Sign in normally on the TradingView
homepage in the default browser, then run `tv mcp login` and complete consent.
TradingView Desktop and a separate Codex MCP configuration are not required.
See the [official service requirements](https://www.tradingview.com/mcp/docs).

| Task | Commands under `tv mcp` |
| --- | --- |
| Authentication and local credential state | `login`, `status`, `logout` |
| Symbol discovery and fields | `search`, `columns`, `symbol`, `symbols` |
| Recent OHLCV | `bars`, including daily/weekly/monthly and six intraday intervals |
| Independent screening | `screener` |
| Watchlist and simple price-alert operations | `watchlist`, `alert` |
| Financial statements and estimates | `financials`, `financial-history`, `forecasts`, `earnings` |
| News and company documents | `news`, `news-story`, `documents`, `document` |
| Economic releases and dividends | `economic-symbols`, `economic-data`, `economic-calendar`, `dividends` |

MCP data uses separate versioned JSON contracts. Returned/missing/unreported
results, null values and unknown data conditions stay explicit. Successful
communication does not prove historical coverage, realtime entitlement or
suitability for analysis/backtesting. Existing `tv bars` and `bars.v1` retain
their WebSocket source and date-range behavior. MCP bars support recent counts,
not arbitrary historical windows or automatic paging.

Watchlist and price-alert changes require an explicit target and effect. Their
responses distinguish mutation acknowledgement from readback. Uncertain changes
are not replayed. Adding a watchlist symbol already present can move it; changing
alert settings reactivates the alert, and deleting an alert removes its history.
MCP price alerts do not replace Pine-condition alerts or selected Desktop state.

## Credentials and platforms

- macOS uses Keychain. Verify the executable and dedicated item before allowing
  access; a replaced unsigned/development binary may require renewed consent.
- Windows uses Credential Manager. Native state-directory security checks use
  Windows APIs rather than spawning PowerShell, with protected ACLs and structured
  reasons/numeric Win32 diagnostics.
- Linux uses a session D-Bus Secret Service such as GNOME Keyring, with a persistent
  default collection. Container and Linux CI checks cover synthetic credential
  storage, reuse, update, restart and deletion. Graphical Linux OAuth remains
  unverified; the CLI requires a working user session, service and browser.

Ordinary commands do not display credential prompts or fall back to plaintext
storage. Initial setup/unlock is explicit through login. If a store requires
confirmation specifically for deletion, use the OS credential manager; login
alone does not approve that deletion. `status` checks local presence/expiry,
not server acceptance. `logout` removes the local record, not remote consent.

## Standalone agent skills

Each archive now supplies seven skills with the references needed inside each
skill directory: `account-management`, `market-data`, `chart-analysis`,
`pine-develop`, `replay-practice`, `screener-workflow`, and `strategy-report`.
Copy a complete skill directory to attach it independently.

The new account skill covers watchlists and simple price alerts through official
MCP. Data-only tasks prefer MCP where its capabilities and authentication fit;
explicit source selections are respected. Chart/Pine evidence, saved Desktop
screens and historical date ranges keep their appropriate existing routes.
Package checks enforce isolated skill references, shared-guidance consistency,
agent-guide parity and the explicit runtime allowlist.
