`v0.40.0` adds structured watchlist entries and strengthens Desktop price-alert
creation confirmation.

## Read watchlist sections and saved order

`tv mcp watchlist get <ID>` now includes `watchlist.entries`, alongside the
unchanged `symbols` array. Each entry is either a symbol or a section:

```json
[
  {"kind": "section", "name": "Candidates", "collapsed": true},
  {"kind": "symbol", "symbol": "NASDAQ:EXAMPLE"}
]
```

Entries preserve saved order, duplicate symbols, same-name sections, empty
sections and symbols before the first section. Collapsed sections still include
their members. `collapsed` describes saved account state, not unsaved Desktop
state. Positions are local to the snapshot, not stable section identifiers.
Unknown contents produce `entries:null`; an empty list produces `entries:[]`.
Malformed section encoding fails instead of being treated as a symbol.

The same fields appear in list results and mutation readback snapshots. Reads
do not activate a list or require Desktop. Existing completeness and mutation
confirmation guarantees are unchanged. Section editing and movement are not
added by this release.

## Confirm price-alert identity and settings

Desktop `alert create` now requires the creation response ID to identify exactly
one saved row that was absent before the request. Matching content from another
concurrent alert cannot confirm creation. Saved symbol settings, exact price,
condition, frequency, message, notifications, auto-deactivation and expiry are
checked. Symbol-marker key order and expiry truncation to seconds are handled.

Simple price conditions are saved with resolution `"1"` and
`cross_interval:true`, while the outer resolution retains the chart timeframe.
Creating from a daily chart does not request a daily-close trigger. This
normalization does not apply to indicator or drawing conditions.

Successful results include:

```json
{
  "created": true,
  "confirmation": {"identity": "matched", "settings": "matched"},
  "activation": {"state": "pending"}
}
```

Activation is reported as `active`, `pending` or `unknown`, without automatic
waiting or reactivation. Pending means inactive with explicitly empty stop/error
fields; it does not promise eventual activation. Unknown means status data is
missing or contradictory. Saved-settings confirmation does not prove notification
delivery.

An attributed settings mismatch, unavailable settings or stopped alert returns
an error with `created:true`, its ID, `confirmation` and `activation`. The reasons
are `settings_mismatch`, `settings_unavailable` and `activation_stopped`.
Unattributable outcomes, including failed readback or lost execution results,
remain `created:null` with `creation_outcome:"unknown"`. Proven preflight failures
retain `created:false`. Neither kind of failure authorizes a blind create retry.

CLI arguments, notification defaults and official MCP alert operations are
unchanged. There is no automatic retry, cleanup or DOM/MCP fallback.

## Dependencies

The release updates rmcp from 3.5.1 to 3.7.0 and Tokio from 1.53.3 to 1.54.1,
with compatible transitive updates including TLS certificate support, Unicode
data and ctutils 0.4.4. Distribution targets and archive contents are unchanged.
