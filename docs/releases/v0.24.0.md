This release focuses on operational robustness and input clarity. It hardens
the normal macOS TradingView Desktop launch path, makes `tv bars` easier to
use with bare symbols, adds a narrow `tv events` readback for earnings and
dividends, and trims packaged runtime skills so agents load less unnecessary
context.

## Highlights

- Hardened `tv launch` on macOS. The normal no-path launch path now uses the
  system app launcher instead of direct binary spawning, while explicit
  `--path` and `--kill-existing` remain opt-in.
- Added Desktop-free bare symbol resolution for `tv bars`. Inputs such as
  `AAPL` can resolve through TradingView symbol search, and `bars.v1` reports
  `requested_symbol`, `resolved_symbol`, and `symbol_resolution` so agents can
  explain what was typed and what was actually used.
- Added `tv events <SYMBOL>` for narrow scanner-backed earnings and dividend
  readback with `contract_version: "events.v1"`.
- Reduced runtime skill context load by splitting market data interpretation,
  chart analysis, and multi-symbol scan into short workflow-oriented
  `SKILL.md` files plus detailed source-boundary references.

## Behavior Notes

- `tv launch` does not implicitly kill existing TradingView Desktop sessions.
  Use `--kill-existing` only when that effect is intentional.
- `tv bars` remains the Desktop-free historical bars source. Bare-symbol
  resolution uses symbol search only; selected charts, scanner quotes,
  quote-data, Replay, and chart export are not used as hidden fallbacks.
- Use `EXCHANGE:SYMBOL` when the exchange must be fixed. If an agent runs a
  bare-symbol bars command, it should report both the requested and resolved
  symbols.
- `tv events` is not a full event calendar. It reshapes scanner fundamentals
  fields for symbol-scoped earnings and dividends and does not infer timezone,
  confirmed status, ranking, recommendation, or trading meaning.
- Runtime skills are shorter by design. Detailed `tv bars`, `tv events`,
  quote-data, selected-chart export, Replay, JSONL, and unsupported-feature
  notes remain available in skill references and are loaded only when needed.

## Packaging

Release archives include the `tv` binary, README, changelog, license,
user-facing agent guides, runtime-oriented skills, and the English and
Japanese getting-started docs. Development-only skills and the broader
repository docs remain excluded.

## Validation

The release-prep checks cover workspace metadata, release package staging, a
locked release build, staged archive contents, Rust formatting, Clippy,
workspace tests, version readback, diff hygiene, and public-doc safety scans.
