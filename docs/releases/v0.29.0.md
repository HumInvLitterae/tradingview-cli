`v0.29.0` makes TradingView Desktop transport failures easier to diagnose
without adding automatic retry or changing existing error behavior.

## Highlights

- Desktop CDP connection errors may now include a public-safe `failure_stage`
  detail for target listing, target selection, WebSocket connection, method
  calls, event waits, or an unknown transport boundary. Existing error kinds,
  messages, exit codes, and command behavior are preserved.
- Runtime guidance now recommends resolving the intended Desktop target once,
  reusing the returned `target_cli_args` across consecutive chart reads, and
  rediscovering only after selection failure, target-set change, or an
  intentional chart change.
- Deterministic transport fixtures verify stage attribution, absolute
  deadlines, event-queue limits, ambiguity handling, malformed output, and
  public-safe evidence. Four pinned Node.js contracts continue to execute the
  generated study-value, Pine, indicator-insertion, and three-point-drawing
  JavaScript used by production paths.

## Boundaries

This release does not add retry, reconnect, a shared session, a broker,
generalized waits, timing metadata, or an indicator-search command. Source
inventories and bounded live investigations were release evidence rather than
new runtime capabilities. Their reviewed outcomes keep retry deferred and
route unattributed chart-read slow tails to a future measurement candidate.

The CLI continues to fail closed on ambiguous Desktop target selection. In a
multi-chart workflow, use `tv tab list` or readiness output to obtain explicit
target arguments and keep using that handoff for subsequent chart-dependent
commands.

## Validation

The v0.29 completion and architecture audit found no release-blocking issue or
required refactor. Release builds remain gated by the complete Rust workspace
baseline and four separately pinned Node.js `24.18.0` JavaScript contracts.
Ordinary Cargo tests remain Node-independent.

Release archives continue to use the explicit eight-skill runtime allowlist
under both packaged skill roots and exclude development-only skills, plans,
notes, and local project ledgers.
