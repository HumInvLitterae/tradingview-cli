`v0.35.0` adds offline contracts for chart-analysis commands and preserves
unknown OHLCV values instead of replacing them with zero.

## OHLCV migration

Selected-chart `ohlcv` now returns null for missing, non-numeric or non-finite
numeric cells. Genuine zero remains zero. The same rules apply to raw bars,
summaries, `export chart-bars --summary` and Replay OHLCV attachments.

High/low and volume aggregates require the corresponding value in every returned
bar. Endpoint-derived changes require known first-open and last-close values;
change_pct also requires a nonzero open. Unknown dependent results remain null
while other known fields stay available. For example, volumes 10 and missing
produce volume:null and avg_volume:null; volumes 10 and genuine zero still
produce 10 and 5.

Consumers that require numeric fields or a string change_pct must accept null
and handle unavailable values before calculation or display. Do not turn null
back into zero. Malformed timestamps and unavailable/empty chart bars remain
errors. Data sources, count limits and operation effects are unchanged.

## Offline chart contracts

```sh
tv schema ohlcv
tv validate -- ohlcv --summary --count 100
tv schema data labels
tv validate -- data labels --filter Example --max 20 --verbose
tv schema data tables
tv validate -- data tables --filter Example
```

`schema` and `validate` now support OHLCV raw/summary outputs and Pine graphics
lines, boxes, labels and tables through the existing cli_schema.v1 and
cli_validate.v1 contracts. These checks need no Desktop, credentials or provider
access and do not execute the candidate command. OHLCV count keeps its default
100 and clamp to 1..500; labels keeps its per-study max behavior, including zero.
Tables has neither max nor verbose.

Schemas describe existing output structure, including nulls and optional verbose
fields. Study identity, primitive coverage, coordinates/styles, count arithmetic
and runtime data quality remain unchecked. Table row strings remain lossy;
schema conformance does not reconstruct a typed rectangular table or establish
trading levels. Successful invocation validation leaves runtime:not_checked.

## Legacy alert prices

Legacy Desktop alert rows now expose a simple-price threshold as condition.value
when that field is absent. Projection requires an exact cross/cross_up/cross_down
condition with ordered barset/value series and one finite numeric threshold.
Genuine zero and existing values, including null, are preserved. Study-based or
ambiguous conditions remain unprojected, and raw series stay omitted.

Symbol markers are unchanged; a projected price does not establish symbol,
currency or adjustment equivalence. Existing uncertain-readback behavior and
explicit MCP/legacy source selection are retained.

## Dependencies and documentation

Tokio is updated to 1.53.2 and Mio to 1.2.4, alongside other compatible transitive
updates. These include upstream Windows process and named-pipe cleanup fixes.

Packaged README links now resolve to bundled guides or online repository
resources. Archive reference checks also cover README and CHANGELOG. Runtime
skills remain independently attachable, with identical real files in both
agent skill roots.
