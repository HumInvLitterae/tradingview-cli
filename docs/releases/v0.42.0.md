`v0.42.0` makes Screener changes report what was saved separately from what
happened to the panel, fixes Screener filter and screen commands in TradingView
Desktop 3.4.0, and lets `watch compare` reuse quote connections.

## Screener results separate saved data from cleanup

After a confirmed filter or screen change, a panel that fails to close no longer
turns the result into an error. The command succeeds and adds `cleanup`, which is
omitted when the panel closed:

```json
{
  "success": true,
  "command": "screener",
  "data": {
    "action": "filter_remove",
    "removed": true,
    "cleanup": {
      "restored": false,
      "error": {
        "kind": "internal_api_unavailable",
        "message": "Stock Screener dialog did not close after Escape"
      }
    }
  }
}
```

This applies to filters add, modify, remove and clear, and to screen create,
save-as and rename. Dry runs, reads, already-matching filters, `screens save` and
`screens switch` keep a failed close as an error. A failed visible refresh after
a confirmed storage change also succeeds, with
`visible_refresh.reason: "refresh_failed"`.

A storage write whose readback fails now adds `details.write_outcome:
"uncertain"` with `save_result` or `delete_result`. A save or delete request
that times out, loses its connection or throws before an answer adds
`write_outcome` alone, because it may have been applied. A readback that cannot
be read in full counts as failed: a body that is not a screen list or document,
filters or columns that are neither a list nor `null`, or entries without an id
or title. Inspect storage before retrying.

**Migration:** automation that treated these errors as failed writes must read
`cleanup`, `visible_refresh` and `details.write_outcome` instead.

## Screener fixes for Desktop 3.4.0

- `filters add` failed with `add_button_not_found` every time, and filter edits
  closed the Screener panel they were working in. Popups are now closed with
  Escape sent inside the popup and only while it is visible.
- `screens switch` and `screens create` from a screen with unsaved changes fail
  with `details.reason: "unsaved_changes"` and `details.dialog_closed`. They
  close the save-changes dialog with its close button, which keeps the screen and
  its changes; they never save or discard them.
- `screens list` returns only the title menu's recent-screen items. It no longer
  lists the auto-save toggle or an entry joining several names.
- When the `filters add` search does not open while Desktop is not in front, the
  error adds `page_visibility: "hidden"` and a `next_action_hint`.
- Screener commands that open the panel now try to close it after errors too.

## Known limits in Desktop 3.4.0

- `filters add` and `modify` leave the screen with unsaved changes. Save or
  discard them before switching or creating a screen.
- Numeric `filters modify` through the UI fails before writing with "manual
  settings button not found". The storage path is unaffected.
- `screens save-as` creates the copy, then fails with "title did not change"
  because the docked panel keeps showing the original. The copy holds only the
  saved version. Check the list before retrying, because a retry creates another
  copy.

## Quote connection reuse

`tradingview_market::QuoteClient` reads batch quotes over HTTP connections kept
between calls. `watch compare` uses one for the whole run; its output is
unchanged.
