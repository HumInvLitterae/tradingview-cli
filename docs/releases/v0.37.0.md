`v0.37.0` adds named Pine script creation and opt-in indicator-alert verification.
It also preserves native study input IDs and reports uncertain alert creation
outcomes without implying that nothing was created.

## Create a saved Pine script from a file

```sh
tv pine create --name "My indicator" --file indicator.pine
```

The command uses the selected TradingView Desktop session to save a new cloud
script. It rejects existing names, then verifies the new script ID, revision,
and saved source. It preserves the current editor and chart; it does not open
the saved script or add a study.

Persistence and compilation have separate results. `saved:true` and
`source_verified:true` confirm the saved revision and source. Compilation
reports `true`, `false`, or `null` when evidence is unavailable. A saved script
with compilation errors remains saved. An uncertain save or readback returns
`saved:null` and `save_outcome:"unknown"`. Inspect saved scripts before retrying;
the command does not retry automatically. Existing editor-bound `pine save`
behavior is unchanged.

## Verify an indicator-alert condition and its inputs

```sh
tv alert create-indicator --script "My indicator" --file indicator.pine \
  --condition-title "Signal" --verify --dry-run
```

`--verify` checks the selected condition against the exact saved compiled
revision. A script with user inputs requires one chart study matching that
revision. Multiple matching instances require `--study-id <ID>`, which selects
the exact chart entity and implies verification. Input values keep their native
IDs. A script with no user inputs needs no chart study unless one is explicitly
selected.

The verified preview reads saved metadata and any required chart inputs without
listing or creating alerts. Remove `--dry-run` to request creation after the same
checks. Passing preview does not prove provider acceptance, complete created-alert
identity, or notification delivery. No study is inserted or changed.

Without the new flags, the existing selection path and successful output shape
remain available. The following fixes apply to normal creation with or without
verification flags.

## Correct input IDs and uncertain outcomes

User-input values are no longer renumbered by their position among system
fields. Missing, duplicate, undeclared, or unverifiable inputs stop before alert
operations. `input_metadata.input_count` counts verified user inputs.

Once creation may have been dispatched, request failures, unreadable responses,
failed readback, and missing evaluation results report `created:null` and
`creation_outcome:"unknown"`. Confirmed preflight non-creation remains
`created:false`. Inspect account state before repeating an uncertain request;
no automatic retry is added.

## Rust API compatibility

The existing `IndicatorAlertRequest` and `alert_create_indicator` entry point
remain available. Rust callers can choose `alert_create_indicator_verified`
with `IndicatorStudySelection`, or create a saved script with `pine_create`.
Consumers matching the public clap enums must handle the new `PineCommand::Create`
variant and the added indicator-alert option fields.

## Verification scope

The complete feature source passed 1,183 Rust tests, full-workspace Clippy,
formatting, and the pinned JavaScript contract gates. Synthetic cases cover
lost responses, malformed metadata, duplicate inputs and studies, and uncertain
save/create outcomes.

Bounded Desktop checks confirmed a no-input verified preview, input-bearing
previews with automatic and explicit study selection, and duplicate rejection.
A new synthetic script passed real save and independent revision/source readback;
repeating its name was rejected. Existing editor state, chart studies and inputs,
and saved catalog entries were preserved. The synthetic saved script is retained
for reuse. Normal live alert creation and notification delivery were not tested.
