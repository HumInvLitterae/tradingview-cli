This feature release expands market discovery, Stock Screener operation, and
API-backed account mutations after `v0.1.1`. It also refreshes release
packaging and project documentation before the next investigation phase.

## Added

- Added read-only `tv scanner scan` for broader market discovery with exchange,
  sector, industry, stock type, price, volume, performance, RSI, and
  recommendation filters.
- Added a much larger Stock Screener surface: saved-screen listing and
  switching, guarded screen lifecycle commands, filter add/modify/remove/clear,
  and storage-backed column config/add/remove/reorder.
- Added `tv watchlist add-bulk` for bounded batch additions with duplicate
  reporting and optional partial-success output.
- Added API-backed `tv watchlist add` and `tv watchlist remove` for active
  custom watchlists, with readback verification and DOM fallback only when the
  API cannot be used before mutation.
- Added API-backed `tv alert create`, with alert-list readback verification and
  visible-dialog fallback only before a create request is sent.
- Added `tv quote [SYMBOL]` for symbol-targeted quote reads with temporary
  chart switching and verified restoration.

## Changed

- Refreshed release-packaged runtime skills and agent guidance, including the
  `screener-workflow` skill while keeping `replay-practice` packaged for
  bounded replay practice.
- Added stable root docs for architecture, development, release packaging,
  breaking JavaScript CLI differences, and internal TradingView API boundaries.
- Archived completed planning documents so `docs/plans/` now keeps only
  active/future plans and the plan index at the root.
- Recorded the post-next-release direct HTTP feasibility plan for future
  investigation without changing the current TradingView Desktop session model.

## Fixed

- Fixed `tv alert delete --id` and `tv alert delete --all` to use the alert
  delete endpoint shape verified by live cleanup while preserving absence
  post-checks.

## Notes

- This release keeps the Rust JSON envelope contract: successful command
  payloads live under `data`.
- `columns reset` and broad multi-option/free-text Screener filter editing
  remain deferred until stronger evidence exists.
- Direct HTTP operation without TradingView Desktop page-session context is
  planned as future research, not part of this release.
