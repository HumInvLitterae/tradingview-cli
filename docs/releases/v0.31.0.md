`v0.31.0` adds bounded one-minute historical bar ranges and more actionable
Desktop-free bars failure diagnostics.

## Highlights

- `tv bars <SYMBOL> --timeframe 1 --from YYYY-MM-DD --to YYYY-MM-DD` now uses
  the same bounded date-range contract as the existing supported timeframes.
  The existing `1m` alias normalizes to the same path.
- One-minute results preserve `bars.v1`, period-start timestamps, inclusive
  calendar-date input with half-open timestamp filtering, the 5,000 returned-
  bar cap, and the existing requested, returned, coverage, and truncation
  fields.
- Desktop-free bars errors may include additive `source_failure_stage`
  details. The closed vocabulary identifies symbol search, request
  preparation, WebSocket connection, session or series setup, response wait,
  protocol processing, heartbeat send, pagination, empty source results, and
  conservative unknown boundaries.
- Existing error kinds, messages, details, and exit codes remain unchanged.
  The stage locates a failure; it does not authorize retry or fallback.

## Workflow

Use an exchange-qualified symbol when deterministic identity matters:

    tv bars NASDAQ:AAPL --timeframe 1 --from 2026-01-05 --to 2026-01-09

Date-range mode returns at most 5,000 bars. Larger historical workflows should
use explicit non-overlapping date windows and merge them downstream while
preserving the reported range and coverage fields.

Market closures, holidays, halts, entitlements, and source exhaustion remain
represented conservatively. The CLI does not synthesize missing bars or infer a
complete exchange calendar.

## Boundaries

This release does not add retry, reconnect, timeout changes, fallback, source
substitution, a shared session, or a broker. It does not widen date-range
support to `3`, `45`, `120`, `180`, or `240`, raise the 5,000-bar cap, add a
calendar source, or package private downstream datasets.

The retained product comparison and the bounded live checks used during
development were release evidence, not additional runtime capabilities.

## Validation

The frozen candidate passed focused bars contracts, strict workspace Clippy,
the complete Rust workspace suite and doctests, public hygiene, workflow and
package checks, and a locked release build. One owner-approved bounded
production-binary comparison covered a single fetch window, an additional
500-bar window, and a closure-boundary case without retaining private inputs.

Release archives continue to use the explicit runtime-skill allowlist under
both packaged skill roots and exclude development-only skills, plans, notes,
and local project ledgers.
