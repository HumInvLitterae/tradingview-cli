`v0.34.0` adds offline output schemas, invocation checks and official technical
snapshots, with clearer chart-analysis results and safer legacy account operations.
This is a release-note draft; candidate CI and final version preparation are pending.

## Offline schemas and invocation checks

```sh
tv schema values
tv schema mcp bars
tv validate -- values
tv validate -- mcp bars NASDAQ:EXAMPLE --timeframe 1D --count 20
```

`schema` exports self-contained JSON Schema 2020-12 documents for `values` and
`mcp bars`. It describes known output structure while leaving dynamic study
values, runtime meaning and error details explicitly unchecked. Null, short and
empty results remain valid observations; schema conformance does not prove
freshness or completeness.

`validate` checks argv after `--` without an executable name. It uses the real
parser and shared local request rules for the same two command paths. Known
unsupported commands return `unsupported`, and runtime checks remain
`not_checked`. It does not execute the candidate or read its input files.
Use it when constructing uncertain arguments rather than before every read.

## Official technical snapshots

```sh
tv mcp technicals NASDAQ:EXAMPLE --timeframe 1D
tv spec mcp technicals
```

The independent MCP command returns `mcp_technicals.v1`: 23 indicator slots,
the official `summary` object and existing provider/client evidence fields.
Missing indicators are null; zero is retained. `available` means some known
observation exists, and `empty` remains distinct from provider failure. Client
receipt time does not establish market-data time, delay, adjustment, session or
finality. Ratings remain provider assessments without local trading thresholds.

The ten documented timeframes include `2h`; this does not extend `mcp bars`.
Daily live qualification succeeded with 21 non-null indicators and matching
symbol/interval echoes. Weekly qualification returned a provider-internal 429;
monthly/two-hour live success remains unverified. There is no historical
indicator series, local calculation or automatic source fallback.

## Analysis and account reliability

- MCP data/bar failures can include bounded provider-error clues. Textual rate
  or Screener clues do not establish HTTP status, quota scope or reset timing.
- `data equity` identifies its extraction branch and confirmed series meaning,
  preserves zero drawdown and retains unavailable/unknown outcomes.
- Snapshot/compare follow-up hints describe chart changes and screenshot file
  writes separately. Consumers should update expectations for chart-quote effects.
- Legacy alert-list reads reject unavailable or malformed responses rather than
  treating them as empty lists. Price-alert creation uses the verified API path.
- Legacy watchlist writes do not replay uncertain mutations through DOM, and
  readback requires the original list. Prefer official MCP account operations
  when they meet the task and authorization is available.

Runtime market-data/chart-analysis skills include the new routes and result
limits and remain independently attachable. Existing command defaults and
provider routing are retained.

## Dependencies

rmcp is updated to 3.5.0 and tokio-rustls to 0.26.6. The client follows SDK
protocol negotiation defaults; both older and current protocol reply fixtures
pass. Explicit null structured results are preserved during SDK decoding.
Successful live reads do not establish the cause of earlier provider failures.
