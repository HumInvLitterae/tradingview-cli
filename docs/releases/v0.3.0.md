This release makes the Rust-native `tv` CLI more reliable for agent and operator workflows, especially where previous commands depended on fragile visible UI state.

## Highlights

- Added explicit chart target handoff with `tv --target-id <ID> ...` and removed the old `TV_CDP_TARGET_ID` public contract.
- Added Desktop-free symbol reads through `tv info <SYMBOL>` and scanner-backed `tv quote <SYMBOL>`, so one-off symbol metadata and quotes do not require mutating the visible TradingView chart.
- Added `tv screener open --full-page` to prepare a full-page Stock Screener target and return reusable `target_cli_args`.
- Improved Screener operations with storage-backed column mutations and storage-backed numeric filter modification where the saved-screen schema can be safely verified.
- Added guarded Pine `alertcondition()` discovery and alert creation with `tv pine alertconditions` and `tv alert create-indicator`.
- Improved API-backed watchlist and alert mutations with readback verification and safer fallback boundaries.
- Improved TradingView Desktop compatibility by defaulting CDP to `127.0.0.1`, avoiding initial CDP domain-enable calls, and documenting the current Windows Store/MSIX launch boundary.

## CLI And Workflow Changes

- `tv tab list` and related target errors now point agents toward `target_cli_args`.
- `tv ohlcv` failures include richer chart-bars readiness details so agents can recover by checking target state instead of retrying blindly.
- `tv draw position` accepts `--direction <long|short>` as an alias for the positional direction argument.
- Runtime skills and packaged agent guidance now emphasize `--target-id`, Desktop-free `info` / `quote`, and full-page Screener setup.

## Internal Changes

- The repository root is now a virtual Cargo workspace.
- Shared package metadata and dependency versions are centralized at the workspace root.
- Reusable internal crates now cover core JSON/error contracts, I/O-free models, Desktop-free market reads, scanner reads, Pine static/check helpers, and CDP target/runtime primitives.
- The CLI package has a thinner binary entrypoint, an application runner layer, split operation adapters, and clearer operation/model boundaries.

## Packaging

Release archives continue to include the `tv` binary, README, changelog, license, user-facing agent guides, and runtime-oriented skills only. Development-only skills are intentionally excluded.

## Notes

- This project is not affiliated with TradingView Inc.
- The non-public TradingView surfaces used by the CLI remain best-effort and can change.
- The release does not add an MCP server, a standalone authenticated TradingView HTTP client, cookie/session import or export, or trading bot workflow packs.
