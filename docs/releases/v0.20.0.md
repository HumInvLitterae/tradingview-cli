This release makes `tv bars <EXCHANGE:SYMBOL>` more useful for reproducible
historical sample preparation by extending date-range reads from daily bars to
weekly and monthly bars. It also improves first-run guidance for release users
and agents through bundled English and Japanese getting-started docs.

## Highlights

- Added `tv bars <SYMBOL> --timeframe 1W --from YYYY-MM-DD --to YYYY-MM-DD`
  and `tv bars <SYMBOL> --timeframe 1M --from YYYY-MM-DD --to YYYY-MM-DD`.
- Daily, weekly, and monthly date-range reads share the existing Desktop-free
  `bars.v1` source boundary and remain separate from selected-chart commands.
- Added `range_alignment` readback so agents and downstream tools can see that
  weekly and monthly bar timestamps are period anchors and that range filtering
  uses timestamps within the requested inclusive calendar range.
- Release archives now include `docs/getting-started.md` and
  `docs/ja/getting-started.md` for non-developer setup, first checks,
  TradingView Desktop readiness, and agent-assisted use.

## Behavior Notes

- `tv bars --from --to` supports date-range mode for `1D`, `1W`, and `1M`.
  Intraday date-range reads remain deferred.
- `--to` is an inclusive calendar date. In date-range mode, `--count` remains a
  safety cap and defaults to 500.
- For weekly and monthly bars, a bar is included when its timestamp is inside
  the requested range. A period that overlaps the first requested days can be
  omitted when the bar timestamp falls before `--from`; read `range_alignment`
  and `range_coverage_status` before interpreting coverage.
- `tv range` still moves the selected Desktop chart viewport. It is not a
  historical export contract for `tv ohlcv`.
- `tv bars` remains a Desktop-free bounded historical bars read. It does not
  rank, score, recommend, trade, or mix scanner, chart, quote-data, observe, or
  stream sources.

## Packaging

Release archives include the `tv` binary, README, changelog, license,
user-facing agent guides, runtime-oriented skills, and the English and
Japanese getting-started docs. Development-only skills and the broader
repository docs remain excluded.
