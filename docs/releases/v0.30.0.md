`v0.30.0` adds explicit chart screenshot attachments to bounded Replay logs
and corrects the existing post-step Replay-running summary.

## Highlights

- `tv replay log` can opt in to one chart screenshot per successful step with
  `--attach-chart-screenshot --screenshot-output-dir <DIR>`.
- Screenshot paths are deterministic and refuse overwrite. A screenshot
  failure is reported as an attachment error without changing Replay step
  success, failure counts, or the run end reason.
- Chart screenshot and OHLCV summary attachments can be requested together.
- `replay_left_running` now reflects the post-step Replay state already
  returned by the Replay operation.

## Boundaries

This release does not add public timing metadata, timeout changes, retry,
reconnect, automatic foreground activation, indicator search, shared sessions,
or a broker. Chart-read latency attribution and renderer foreground feasibility
were bounded release investigations, not additional runtime capabilities.

Replay screenshot files are written before their JSONL step event is emitted.
If the output consumer disconnects at that boundary, the current step's PNG may
exist even though its JSONL event was not consumed; no later step or screenshot
is attempted.

## Validation

The frozen candidate and its compatible lockfile-only dependency refresh passed
the complete Rust workspace baseline, strict Clippy, public hygiene, workflow
and package checks, and focused independent review. Release builds remain gated
by four pinned Node.js `24.18.0` contracts for study values, Pine, indicator
insertion, and three-point drawing.

Release archives continue to use the explicit eight-skill runtime allowlist
under both packaged skill roots and exclude development-only skills, plans,
notes, and local project ledgers.
