This release improves downstream evidence compatibility and quote-data
troubleshooting. It adds stable compare movement readback for regular-session
percent change and a narrow diagnostic command for explicit Desktop-backed
quote-data availability, without mixing scanner, chart, or quote-data sources.

## Highlights

- Added `items[].movement.regular_change_percent` to `tv compare` so
  downstream tools can read regular-session percent-change evidence from a
  stable compare-level path.
- Added `summary.movement_coverage` to report movement evidence availability
  across validated requested compare items.
- Added `tv diagnose quote-data <SYMBOL>` as a read-only diagnostic packet for
  the explicit quote-data source.
- Added public-safe quote-data troubleshooting for Desktop target state,
  bounded WebSocket / `qsd` observation, requested-symbol matching, `rtc`
  availability, scanner freshness reference, and next action hints.
- Hardened the opt-in quote-data live smoke so multi-target Desktop sessions
  can validate a chosen chart target without recording raw target ids.

## Behavior Notes

- `tv compare` still preserves raw `items[].sections.quote.data.change` as the
  source evidence. `movement.regular_change_percent` is additive readback, not
  ranking, scoring, recommendation, or a trading signal.
- `movement.regular_change_abs` is not inferred when the scanner-backed
  compare source does not expose a stable normalized absolute regular change.
- `tv diagnose quote-data <SYMBOL>` is a diagnostic command, not a new price
  source. It does not merge quote-data values with scanner or chart-source
  quote values.
- `tv quote <SYMBOL> --source quote-data` remains explicit and is not part of
  `--source auto`.
- Scanner-backed `tv quote <SYMBOL>` and `tv quotes <SYMBOL>...` remain
  Desktop-free scanner REST reads. They can be delayed; inspect freshness
  metadata when timing matters.
