`v0.31.3` adds build provenance to the existing version surface and refreshes
compatible dependencies.

## Added

- `tv --version` now reports the package release, short source commit, and
  source or build date in one line.
- `tv --version --verbose` reports `binary`, `release`, full `commit-hash`,
  `commit-date`, RFC 3339 `built-at`, `dirty`, and the binary `target` triple.
- Clean builds use the source commit date. Builds with executable-source
  changes append `-dirty` and use the build date. Documentation-only changes do
  not mark the binary dirty.
- `SOURCE_DATE_EPOCH` fixes `built-at` in UTC for reproducible builds. A
  malformed value fails the build instead of silently using the wall clock.

## Changed

- Root `-V` and `--version` are handled explicitly so they can be combined with
  root `--verbose`. Existing subcommand-specific `--verbose` flags are
  unchanged.
- Updated compatible locked versions of `h2`, `icu_provider`, and
  `zerovec-derive`.

## Boundaries

Build provenance identifies the inputs observed while compiling the binary; it
is not a cryptographic signature or supply-chain attestation. Builds without
usable git metadata report `UNKNOWN` rather than failing.

This patch changes no ordinary command JSON envelope, source, timeout, retry,
reconnect, fallback, shared session, broker, workflow, or package-layout
contract. The chart-quote internal error-size refactor preserves behavior and
only restores the strict Clippy baseline.

## Validation

The release is validated with deterministic real-repository provenance tests,
CLI version contracts, the complete Rust workspace suite and doctests, strict
Clippy, a locked release build, four pinned Node.js production-JavaScript
contracts, public hygiene, workflow parsing, source/staged version readback,
and the explicit release package check. Native release jobs remain the final
Linux, macOS Intel, macOS arm64, and Windows target proof.
