# v0.19.0 roadmap draft

This document records the `v0.19.0` direction after the `v0.18.0` release.

Status as of 2026-05-26: `v0.19.0` is treated as released. Daily
`tv bars` date-range historical readback shipped as the Desktop-free source
for reproducible historical bars input. The next roadmap is `v0.20.0`, focused
on weekly/monthly historical range maturity.

## Theme

`v0.19.0` is about historical range bars and reproducible sample preparation.

The goal is not to add realtime feeds, watch loops, chart-source extraction
shortcuts, ranking, or trading recommendations. The goal is to give agents and
downstream tools a stable way to request historical OHLCV bars for a specific
symbol, timeframe, and date range, especially when reproducing older textbook
or source-guided examples such as VCP or cup-with-handle setups.

The important source boundary is that `tv range --from ... --to ...` changes
the selected Desktop chart viewport, and `tv ohlcv --count ...` reads selected
Desktop chart bars, but that pair is not a stable historical export contract.
`tv bars` is the Desktop-free historical bars command, and v0.19 should extend
that command rather than teaching users to rely on viewport movement as data
preparation.

## Lane 1: `tv bars` date-range readback

Status: complete for `v0.19.0`.

`tv bars <EXCHANGE:SYMBOL>` is already a stable Desktop-free historical OHLCV
read with `contract_version: "bars.v1"`, `source: "tradingview_bars_ws"`,
`summary`, `range`, and `source_availability`. Today it is count-based: users
can ask for the most recent bounded number of bars, but cannot request
`2010-01-01` through `2010-12-31` directly.

The first implementation lane added a date-range request mode, starting with
daily bars:

- add `--from <DATE>` and `--to <DATE>` to `tv bars`;
- keep `SYMBOL` exchange-qualified;
- keep `tv bars` Desktop-free and non-mutating;
- do not use `tv range`, selected chart state, screenshots, Replay, or
  `tv ohlcv` as hidden fallbacks;
- preserve existing count-based behavior when no date range is requested;
- reject ambiguous combinations before network access when necessary;
- report exactly what range was requested and what range was returned.

Daily bars are the safest first target because old intraday history can be
more entitlement- and retention-dependent. Intraday date-range reads can be
considered after daily behavior is stable.

## Lane 2: Historical range coverage contract

Status: complete for `v0.19.0`.

Date-range reads must be reproducible and machine-readable. A successful
payload should make it clear whether the returned bars cover the requested
range or only part of it. A failure should explain source availability, not
make a trading or pattern-quality claim.

The additive readback includes fields such as:

- requested range: `from`, `to`, and normalized timestamp form;
- returned range: `first_time`, `last_time`, `bar_count`, and `time_order`;
- coverage status: `complete`, `partial`, `empty`, or `blocked`;
- source availability and public-safe wait summary consistent with existing
  `bars.v1` behavior.

The raw `bars[]` array remains the evidence. Summary and coverage fields are
first-pass readback for agents and downstream tools.

## Lane 3: Source-guided sample workflow clarity

Status: complete for `v0.19.0`.

Docs and runtime skills should teach a clear workflow:

- use `tv bars --from --to` for reproducible Desktop-free historical bars;
- use `tv range` only to move the visible Desktop chart viewport;
- use `tv ohlcv` only when selected-chart CDP bars are the intended source;
- use `tv observe chart` and `tv stream ...` for bounded selected-chart JSONL
  observation, not historical source preparation;
- keep scanner quote, chart quote, quote-data, and bars evidence separate.

This lane exists because downstream reports showed that moving the chart range
can look like source preparation, but it does not currently make
`tv ohlcv --count ...` return old bars for that displayed period.

## Lane 4: Deferred and later candidates

The following remain deferred unless a separate plan changes the boundary:

- intraday historical range reads beyond the first daily-bars slice;
- pagination or large-range batching beyond the initial bounded implementation;
- replay-based source extraction;
- `tv range` plus `tv ohlcv` automatic historical export;
- realtime multi-symbol feed;
- watch or JSONL compare;
- chart-backed compare;
- quote-data auto fallback;
- automatic source mixing;
- standalone `tv events`;
- binary split;
- MCP server work;
- daemon, dashboard, or trading-bot behavior;
- ranking, scoring, or buy/sell recommendations.
