# v0.9.0 roadmap draft

This document records the `v0.9.0` direction after the `v0.8.0` release and
the chart-source quote concurrency audit.

Status as of 2026-05-07: `v0.8.0` has been released. The chart-source quote
concurrency smoke did not reproduce symbol mismatch at near-concurrent widths
2 or 3, but chart-source quote remains a single-symbol selected-chart feed
check rather than a multi-symbol realtime batch source. The first
Desktop-free comparison slice, `tv compare <SYMBOL>...`, is implemented.

## Theme

`v0.9.0` is about Desktop-free comparison and evidence ranking.

The goal is to help humans and agents compare several symbols without
switching the visible TradingView chart across every candidate. Comparison
payloads should preserve source, freshness, missing-value, and per-symbol
errors rather than hiding data quality differences behind a score.

## Lane 1: Symbol Compare

The first implementation slice is `tv compare <SYMBOL>...`.

Initial compare is a Desktop-free, multi-symbol JSON command. It gathers
quote, symbol info, and default fundamentals evidence for each requested symbol
and returns a comparison packet that is easier to scan than running multiple
single-symbol snapshots by hand.

Initial compare should not:

- connect to TradingView Desktop or CDP;
- switch the visible chart;
- use chart-source quote as a loop;
- include screenshots or `tv observe chart`;
- include lab-gated `tv bars`;
- produce buy/sell recommendations.

Chart-backed follow-up belongs in `next_action_hints` or in a separate manual
workflow after comparison identifies finalists.

## Lane 2: Comparison Workflow

`tv snapshot <SYMBOL>` remains the one-symbol evidence packet. `tv quotes` and
`tv scanner scan` remain useful for narrower batch reads and scanner-style row
sets. `tv compare` should sit between those surfaces: broader than snapshot,
but more structured for per-symbol comparison than raw scanner rows.

Good follow-up candidates after initial compare:

- docs and runtime skills that explain `quotes` versus `snapshot` versus
  `compare`;
- opt-in live contract smoke for compare after the command exists;
- small payload polish if downstream agents need clearer per-symbol summaries.

## Lane 3: Chart And Realtime Boundaries

`tv quote <SYMBOL> --source chart` remains correctness-first and
single-symbol. The successful concurrency smoke supports moving compare
forward, but it does not prove chart-source quote is a realtime batch source.

If future evidence captures chart-source mismatch, treat it as a focused patch
lane. Do not solve that by making `compare` switch the chart repeatedly.

Deferred by default:

- chart-backed compare;
- realtime multi-symbol feed;
- automatic screenshot capture;
- `observe chart` expansion for multi-symbol switching;
- daemon or watch behavior.

## Lane 4: Deferred Infrastructure

The following remain out of scope for `v0.9.0` unless a separate plan changes
the boundary:

- stable browserless historical bars;
- browserless streaming;
- standalone `tv events`;
- `tv diagnose`;
- `tvb`, `tvd`, or other alternate binaries;
- MCP server work;
- trading bots or dashboards;
- cookie/session import or export;
- raw TradingView endpoint primitives;
- public-stable crates.io publication promises.

## Current ExecPlan

- `docs/plans/tradingview-cli-symbol-compare.md`

The initial Desktop-free `tv compare` surface is implemented. The next slice
should use downstream feedback to decide between compare workflow docs, an
opt-in compare live smoke, or small payload polish.
