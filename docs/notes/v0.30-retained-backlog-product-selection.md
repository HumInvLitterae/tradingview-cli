# v0.30 retained-backlog product selection

This note records the source-and-workflow comparison used to select one
user-facing product slice for v0.30. It does not authorize implementation by
itself.

## Decision

Select explicit Replay chart-screenshot attachment. `tv replay log` already
owns bounded step advancement, per-step optional attachments, JSONL output, and
attachment counters. The screenshot operation already owns chart bounds,
clipped capture with local-crop fallback, PNG writing, and public metadata. The
slice can compose established boundaries without discovering a new private API.

The feature must remain opt-in, require an explicit output directory, use
deterministic per-step filenames, refuse overwrite, and keep screenshot failure
separate from Replay step failure. It is not automatic Replay export.

## Comparison

Replay screenshot attachment has direct value for bar-by-bar practice and a
bounded local side effect. Remaining intraday ranges still need retention and
coverage evidence. Pine naming introduces account persistence, collision, focus,
and unknown-save recovery risk. Screener reset lacks a reliable default source.
Event fields are scanner-derived and cannot support a complete calendar claim.
Broader Replay or historical export would mix deliberately separate source and
artifact contracts.

Implementation is governed by
`docs/plans/tradingview-cli-replay-screenshot-attachment.md`. Other candidates
remain unpromoted.
