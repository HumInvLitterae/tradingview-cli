# v0.15.0 roadmap draft

This document records the `v0.15.0` direction after the `v0.14.0` release
and the post-release quote-data live smoke target hardening.

Status as of 2026-05-11: `v0.14.0` has been released. The explicit
`tv quote <SYMBOL> --source quote-data` source has command-local
`quote_data.v1` metadata, source-availability diagnostics, unavailable
reasons, public-safe wait-summary counters, and session readback
normalization. The ignored live smoke can now target a specific TradingView
chart during premarket validation without exposing raw target ids in docs.

## Theme

`v0.15.0` is about downstream evidence compatibility and source diagnostics.

The goal is not to rank symbols, recommend trades, add another hidden price
source, or merge quote-data into existing quote paths. The goal is to give
downstream tools stable readback paths for evidence they already use, and to
help agents tell where an explicit quote-data read is blocked: Desktop target
selection, WebSocket traffic, TradingView `qsd` messages, requested-symbol
attribution, or missing `qsd.rtc` readback.

## Lane 1: Compare change evidence compatibility

This lane is complete for the current v0.15 cycle.

Downstream session-mode tooling reported that `compare.v1` could show complete
coverage while still being treated as unavailable because regular-session
percent change was only available through the raw scanner quote path
`items[].sections.quote.data.change`. That raw field is regular-session
percentage change, but downstream tools need a stable compare-level readback
path.

The first implementation slice added additive movement metadata to
`compare.v1`, centered on `items[].movement.regular_change_percent`, while
preserving raw `sections.quote.data.change` as the source evidence. This is
not ranking, scoring, recommendation, or a chart-backed compare source.

## Lane 2: Narrow quote-data diagnostics

This lane is complete for the current v0.15 cycle.

`quote_data.v1` already tells callers whether a bounded quote-data read was
available and why it was unavailable. In practice, operators and agents still
need to run several commands to understand whether the problem is target
ambiguity, absent WebSocket traffic, no `qsd` messages, no matching requested
symbol, or matching symbol messages without `rtc`.

The implementation slice added `tv diagnose quote-data <SYMBOL>`.
This should be a diagnostic packet for the existing explicit quote-data
source, not a new market-data source. It should summarize target discovery,
quote-data availability, and public-safe wait counters in one place. It may
include scanner freshness as a separate reference source, but it must not
merge scanner values with quote-data values.

## Lane 3: Premarket and postmarket evidence maturity

Premarket success evidence remains open.

The `v0.14.0` contract is useful even when quote-data is unavailable, because
unavailable details now distinguish source availability from a missing market
price. Still, premarket and postmarket live evidence should continue to be
collected only through explicit opt-in smokes during the relevant market
phase.

Live evidence remains a release-supporting signal, not a normal CI
requirement. Raw WebSocket frames, raw live payloads, target ids, and
account-local metadata must not be pasted into tracked docs.

## Lane 4: Source choice workflow clarity

The fourth lane keeps source choice understandable.

Scanner-backed `tv quote` and `tv quotes` are Desktop-free scanner REST reads
that can be delayed. Chart-source quote reads the selected chart main-series
last bar and reports `session_boundary`. Quote-data is an explicit
Desktop-backed WebSocket quote-data readback and can report structured source
unavailability. `snapshot` and `compare` remain Desktop-free evidence packets.

Docs and runtime skills should continue to treat these as separate evidence
surfaces. The user or agent may compare them, but the CLI should not silently
combine them or infer trading action from their differences.

## Lane 5: Deferred and later candidates

The following remain deferred unless a separate plan changes the boundary:

- quote-data auto fallback;
- automatic source mixing;
- chart-backed compare;
- watch or JSONL compare;
- realtime multi-symbol feed;
- stable browserless bars;
- standalone `tv events`;
- binary split;
- MCP server work;
- daemon, dashboard, or trading-bot behavior;
- ranking, scoring, or buy/sell recommendations.

`tv diagnose` is no longer only generic backlog, but the initial candidate is
intentionally narrow: `tv diagnose quote-data <SYMBOL>`. A broad
`tv diagnose all` command is not part of the first slice.
