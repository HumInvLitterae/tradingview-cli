# v0.28.0 roadmap

This document records the direction after the `v0.27.0` release.

Status as of 2026-07-14: `v0.27.0` is released from commit `73ee3a2`.
Current planning has moved to `v0.28.0`. The workspace version remains
`0.27.0` until release readiness. The detailed ordered inventory is
`docs/v0.28-work-items.md`, and the first active ExecPlan is
`docs/plans/tradingview-cli-pine-saved-script-binding-safety.md`.

## Theme

`v0.28.0` focuses on Pine and indicator mutation safety plus compatibility
with current TradingView Desktop builds.

The previous release improved current-build chart reads and evidence quality.
The next release should first make existing mutations trustworthy. A command
that opens or inserts the wrong account-linked object is more harmful than a
missing convenience command. Upstream pull requests are evidence and design
input, not patches to copy verbatim; Rust behavior must remain fail-closed,
public-safe, bounded, and independently tested.

Desktop-free reads, selected-chart reads, chart mutations, Pine cloud
operations, Replay operations, and screenshots remain explicit surfaces. The
CLI does not automatically mix sources, rank evidence, recommend trades, or
make trading decisions.

## Pine saved-script binding safety

Priority: highest. Status: implementation, full local validation, and focused
re-review are green; owner-approved disposable-script live evidence remains.
Current plan:
`docs/plans/tradingview-cli-pine-saved-script-binding-safety.md`.

Before this slice, `tv pine open` resolved a saved script and wrote its source
into Monaco with `setValue`. That changed the visible editor buffer but did not
prove that TradingView's active saved-script slot changed. The Rust
implementation has not reproduced an overwrite live, so the live risk remains
`UNCONFIRMED`, but the structural weakness has been removed from the current
local implementation.

Change `tv pine open` to use TradingView's own saved-script opening path and
verify the active script identity after the operation. If the required
internal API or readback is unavailable, return a structured failure without
injecting source or reporting a verified binding. Opening Pine Editor itself
may be required to expose readback. Do not fall back to source-only
`setValue` while reporting success.

The implementation must preserve explicit user intent, keep account-local
identifiers out of tracked evidence, and use owner-approved disposable scripts
for any live mutation matrix. `tv pine save`, compile behavior, named new-script
save, and REST-style overwrite workflows do not expand implicitly in this
slice.

## Current-build indicator insertion

Priority: high after Pine binding safety.

The current `tv indicator add` uses `chart.createStudy` and converts inputs to
an array of `{id, value}` objects. Upstream evidence from TradingView Desktop
3.2.0 reports that this path can reject valid names and that the current
inserter expects an input object keyed by input ID.

Investigate the current metainfo repository and study inserter first. An
implementation may proceed only if it can resolve an exact indicator
description, reject zero or multiple matches before mutation, await the
insertion result, and verify exactly one new study through the post-operation
inventory. Requested and observed inputs must be read back without exposing
source code or account-local metadata. Do not silently fall back to the old
`createStudy` path on a build where the verified inserter is unavailable.

Indicator search remains separate. The deferred dialog-search prototype is
not a fallback for insertion, and insertion does not reopen the deferred
positive-result search command.

## Active Pine Editor and platform shortcuts

Priority: high after indicator insertion, or earlier if it blocks Pine binding
validation.

TradingView can retain hidden Monaco containers after closing, reopening, or
redocking Pine Editor. The current finder can choose the first matching
container or editor even when it is stale. Prefer an editor with text focus,
then an editor owned by the visible Pine container, and only then a conservative
fallback. Verify container ownership rather than assuming global editor order.

Keyboard operations must focus the selected visible editor first. Platform
shortcuts should use the correct macOS modifier instead of assuming Control on
all systems. This work must not auto-confirm Save, Add-to-chart, naming,
external-data, or other dialogs. Locale-specific button lists are not a
substitute for semantic ownership and post-checks.

## Launch environment compatibility

Priority: medium-high and intentionally narrow.

Prevent `tv launch` from passing `ELECTRON_RUN_AS_NODE` to a directly spawned
TradingView process. Some Electron-hosted shells set that variable for their
own child processes; inheriting it can make TradingView run as Node instead of
Chromium and prevent CDP from opening.

The implementation must cover direct spawn deterministically, investigate the
macOS `open` path separately, and classify immediate process exit as a
connection failure rather than successful launch with `cdp_ready: false` when
the evidence is available. It must preserve the no-kill default and explicit
`--kill-existing` boundary.

## Bounded chart-layout and drawing candidates

Priority: medium and capacity-dependent.

A selected-chart right-offset command can create explicit projection space to
the right of the latest bar. It is useful for forward drawings and screenshot
composition, but it must be a separate mutation with finite integer
validation, before/after readback, a reset value, and structured failure. Range
and screenshot commands must not apply it as a hidden side effect.

Native three-point drawings, including parallel channels, are also useful.
They require I/O-free point validation, exact creation verification, and
failure when no new entity ID can be observed. Width-derived convenience must
not replace an explicit third point unless its geometry and sign rules are
defined and tested.

Promote at most one of these features before the completion audit unless the
required safety and compatibility work is already complete and reviewed.

## Windows MSIX package-identity feasibility

Priority: medium and feasibility-only.

Current Rust launch support has prior evidence for direct AppX/MSIX executable
launch. New upstream evidence reports that TradingView Desktop 3.3.0 may need
package-identity-preserving launch through PowerShell. Do not replace the
existing path from a report alone.

A Windows-host investigation should compare direct package launch and
`Invoke-CommandInDesktopPackage`, verify CDP version readback, distinguish
Store/MSIX from standalone installations, bound PowerShell execution, and
define recovery guidance. No stable implementation is promised until that
matrix is reproducible and independently reviewed.

## Retained backlog and exclusions

The retained product backlog includes event date ranges and source
availability, Replay screenshot attachment, remaining intraday bars ranges,
Screener column reset, safe new Pine script naming and save, a complete
calendar source, and explicit Replay or historical-export expansion. These
items remain recorded in `docs/v0.28-work-items.md` and are not implied by the
Pine or indicator work.

CDP auto-reconnect needs a concrete Rust regression before promotion because
ordinary commands reconnect per process and long-running workflows are
bounded. Alert and watchlist mutations require separate security, destructive
operation, post-check, and recovery contracts. Bias inference, ranking,
scoring, buy/sell recommendations, automatic source mixing, MCP server work,
daemon/dashboard operation, cookie/session import, login automation, and
trading bots remain excluded by default.

## Quality gates

Every implementation slice requires focused tests, the full Rust baseline,
public hygiene, contributor-guide parity, and documentation/skill updates when
user or agent workflows change. JavaScript executed inside TradingView must be
tested as executable behavior rather than only as a string when practical;
ordinary Cargo tests must remain Rust-only, with any Node-based contract kept
in an explicit pinned gate.

Run from the repository root:

    cargo fmt --check
    cargo clippy --workspace --all-targets --all-features -- -D warnings
    cargo test --workspace
    cargo metadata --no-deps --format-version 1
    python3 scripts/check-public-hygiene.py
    bash -n scripts/stage-release-package-files.sh
    cmp -s AGENTS.md CLAUDE.md
    git diff --check

Live tests are supplemental unless a current-build compatibility or mutation
safety claim requires them. Such tests must be bounded, owner-approved when
they change account or chart state, and recorded only as public-safe summaries.
