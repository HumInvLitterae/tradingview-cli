# v0.28.0 ordered work inventory

This document is the durable inventory for the `v0.28.0` roadmap. It records
more work than should be active at once so useful upstream discoveries and
retained product candidates are not lost when the repository keeps only one
current ExecPlan.

The order is intentional. Promote one item into a self-contained ExecPlan only
after the preceding required item is implemented, validated, independently
reviewed, and archived. If evidence changes the order, update this inventory,
`docs/v0.28-roadmap.md`, `docs/plans/README.md`, and `CONTINUITY.md` together.

## Global rules

The workspace version remains `0.27.0` until v0.28 release readiness. Use
descriptive work-item and plan names; do not introduce ordinal aliases that
depend on an external numbering scheme. New fields are additive unless a
reviewed safety plan requires a breaking correction.

Desktop-free and Desktop-backed sources remain separate. Chart mutation,
editor mutation, account-linked persistence, and process launch must be
explicit in help and payload metadata. Do not add hidden fallback, automatic
source mixing, ranking, recommendation, or trading judgment. Live evidence
contains only bounded public-safe summaries, never source text, raw DOM, raw
payloads, credentials, session or target identifiers, account-local
identifiers, or machine-specific paths.

## Promotion and handback

Every promoted item gets a fresh self-contained ExecPlan with verified current
facts, an observable outcome, explicit mutation and source boundaries,
deterministic tests, required live evidence, stop conditions, and docs/skill
updates. Upstream pull requests are evidence, not implementation authority.

Implementation handback must state changed behavior, focused and full
validation, live evidence status, residual risk, source and mutation semantics,
documentation and skill synchronization, worktree state, and whether an
independent review remains. This inventory never authorizes a push or another
external mutation.
