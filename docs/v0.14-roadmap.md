# v0.14.0 roadmap draft

This document records the `v0.14.0` direction after the `v0.13.0` release.

Status as of 2026-05-11: `v0.14.0` has been released. The CLI now has an
explicit `tv quote <SYMBOL> --source quote-data` source with bounded
Desktop-backed TradingView quote-data WebSocket readback, command-local
contract metadata, and source-availability diagnostics. The post-release
opt-in live smoke hardening is also complete, so premarket validation can
target the intended chart in multi-target Desktop sessions.

## Theme

`v0.14.0` is about quote-data maturity and source availability clarity.

The goal is to make `quote-data` useful in real workflows without turning it
into an automatic fallback, ranking signal, or hidden source mixer. The command
should tell agents what quote-data evidence was available, what was missing,
and whether the source was unavailable during the bounded wait.

## Lane 1: Quote-data source maturity

The primary lane is `tv quote <SYMBOL> --source quote-data`.

The source currently reads bounded Desktop-backed TradingView `qsd` quote-data
messages and exposes `qsd.rtc`-style readback separately from scanner REST and
chart main-series quote. It is the strongest current candidate for the
right-side visible after-hours panel value observed during v0.13 source
discovery, but it remains an explicit Desktop-backed source.

For v0.14, this source has been matured with command-local contract metadata
and clear availability readback. `qsd.rtc`, `rtc_time`, `current_session`, and
`market_phase` should remain source-labeled readbacks. Do not claim that they
are scanner-style `extended_hours`, and do not infer a trading action,
recommendation, or session classification beyond what TradingView reports.

Premarket evidence is still open. A real premarket live smoke should be run
only during the matching market phase, with public-safe summaries. It should
not block the first contract-metadata slice.

## Lane 2: Source availability and failure readback

The second lane is making unavailable results easier to interpret.

When quote-data has no frame, no matching symbol, or no `qsd.rtc` within the
bounded wait, agents need to know that the source was unavailable, not that the
symbol has no price. The existing unavailable details already avoid raw
WebSocket frames. v0.14 should make the readback more stable and machine
readable by preserving bounded wait, WebSocket event counts, qsd counts,
matching counts, and symbol attribution summaries.

The first implementation slice added `contract_version: "quote_data.v1"` and
explicit `source_availability` readback to success payloads and structured
unavailable details. It kept the existing `quote_data.rtc` shape and avoided
scanner `extended_hours`, chart main-series fields, and raw frame output.

The follow-up implementation slice expanded that contract with
machine-readable unavailable reasons, additional public-safe wait-summary
counts, and session readback normalization. This should let agents tell
whether quote-data saw no WebSocket events, no qsd messages, no matching
symbol, or matching qsd without `rtc`, without reading raw frames or treating
unavailable quote-data as a missing market price.

Status after release: complete for `v0.14.0`. The pre-release audit found no
blocker and the release was completed. Premarket-specific evidence remains a
live-evidence task, and the post-release smoke target selection hardening is
complete.

## Lane 3: Source choice workflow clarity

The third lane keeps source choice understandable.

Scanner-backed `tv quote` and `tv quotes` are Desktop-free scanner REST reads
that can be delayed. Chart-source quote reads the selected chart main-series
last bar and reports `session_boundary`. Quote-data is Desktop-backed
WebSocket quote-data readback and can return structured unavailable details.
`snapshot` and `compare` remain Desktop-free evidence packets.

Docs and runtime skills should keep these boundaries aligned so agents choose
the right source for freshness, extended-hours, and chart-follow-up questions.
`quote-data` must not become part of `--source auto` unless a separate plan
later changes that boundary.

Status after release: complete for `v0.14.0`. The first post-release
validation showed the quote-data command can return public-safe
`quote_data.v1` unavailable details, including `no_rtc`, nonzero WebSocket/qsd
counts, and no raw frames. The follow-up smoke hardening added explicit target
selection to the ignored live smoke, confirming that multi-target Desktop
validation can reach quote-data diagnostics without first failing at target
ambiguity. Premarket `rtc` success evidence remains open.

## Lane 4: Deferred and later candidates

The following remain deferred unless a separate plan changes the boundary:

- quote-data auto fallback;
- automatic source mixing;
- chart-backed compare;
- watch or JSONL compare;
- realtime multi-symbol feed;
- stable browserless bars;
- standalone `tv events`;
- binary split;
- MCP server work;
- daemon, dashboard, or trading-bot behavior;
- ranking, scoring, or buy/sell recommendations.

`tv diagnose` remains deferred as a broad troubleshooting command, but v0.14
raised it from generic backlog to a later candidate if quote-data availability
debugging kept requiring repeated manual checks. The next version narrows that
candidate to quote-data diagnostics first rather than a broad all-purpose
diagnose command.

## Current ExecPlan

- `docs/plans/tradingview-cli-quote-data-diagnostics.md`

The current project direction has moved to the `v0.15.0` roadmap and its first
quote-data diagnostics plan. The completed post-release smoke hardening did
not add new data sources, automatic fallback, ranking, recommendation,
chart-source mixing, scanner extended-hours mixing, public JSON fields, or
`--source auto` behavior.

Result: `v0.14.0` is complete. The next public-version planning starts from
source diagnostics and quote-data availability clarity.
